## 1. 视觉精细化（A 系列）

### A1. classic 主题（贯穿式搜索框 + 浮动按钮）

**【决策 N1】** classic 作为第 6 个主题值加入 `theme` 设置（`auto / light / dark / ink / paper / classic`），`body[data-theme="classic"]`。仅浅色模式（用户处于 dark 系统仍显示浅色，classic 不跟随 prefers-color-scheme）。与「一键恢复经典界面」开关（`options.js:113-128` 关 5 个 v4 功能）正交——两开关都开 = v3 完整方形体验；classic 视觉 + v4 功能开 = 方形外壳 + 新功能。

**【现状定位】**
- 主题应用点：`popup.js:10` `document.body.dataset.theme = store.get('theme','auto')`；token 块 `neat.css:21-158`。
- 当前搜索框圆角 `8px`（`--vbm-radius`）、`#search` 四周 `margin: 2px 2px 4px`（`neat.css:259`）→ 搜索框是「悬浮圆角字段」，非贯穿式。
- 清空按钮已是字段内浮层（`#search-clear`，`visibility` 切换，`neat.css:331-351`）。
- header 几何（harness 实测）：`#search` 396×31、输入框 328×31 r8、`#quick-add-btn`/`#tool-btn` 各 30×30 r8（`margin-inline-start:4px`）。

**【设计】**
`body[data-theme="classic"]` 覆盖块（放 `css/themes/classic.css`）：

| 元素 | classic 覆盖 |
|---|---|
| `#search` | `margin: 0 0 2px`（去左右边距 → 贯穿式通栏） |
| `#search input` | `border-radius: 0`；`border-color` 用 `color-mix(in srgb, var(--vbm-fg) 40%, transparent)`（v3 时代的强灰边） |
| `#quick-add-btn` / `#tool-btn` | `border-radius: 0`；背景 `transparent`→hover `--vbm-bg-hover`（v3 扁平按钮，去掉独立 elevated 卡片感） |
| `#search-clear` | 沿用现有 `visibility` 揭示（输入态浮现，不需改动） |
| `#view-tabs` / `#views` | 回到直角：`border-radius: 0`、无卡片背景（`background: transparent`）、列表容器去 inset shadow |

「浮动按钮」语义：按钮紧贴搜索框右侧成组（现有 flex 布局保留），仅去圆角扁平化；「贯穿式」= 搜索框左右贴窗口边。其余通用结构（字体、行高、hover 态）沿用 token，保证维护成本低。

**【实施要点】** ① `store.js:64` 的 `theme` 默认值不变（默认仍 auto）；② 选项页主题下拉加「Classic（经典浅色）」项 + i18n key；③ 新增 `css/themes/classic.css`（随 A2 解耦一并建立目录）；④ `popup.js` 应用逻辑无需改（dataset.theme 已有）。

**【验收】** ① 选项页选 classic → popup 搜索框通栏方角、两按钮扁平、tab/列表直角；② classic 下输入文字 → 清空按钮浮现；③ `theme.test.js` 补 classic 契约（body class 应用 + 关键元素 radius=0）；④ harness 截图 `theme-classic-tabs.png`（shots-themes 加 classic）。

### A2. modern 主题 R 角迭代（radius 分层 + 卡片化 + tab 重绘 + CSS 解耦）

**【决策 D2/N2/N3】** ① 半径收敛为**分层 token**（学 VS Code 高程模型）；② 主视图列表区做**卡片式圆角容器**（`.view` 卡片 + 呼吸边距）；③ tab 用**扁平圆角 + 滑动指示条**（否决弧形过渡）；④ **CSS 解耦**：主题相关规则抽到 `css/themes/`，neat.css 只留通用结构。

**【现状定位】**
- 统一 token `--vbm-radius:8px`（`neat.css:41`）已覆盖搜索框/按钮/菜单/对话框/下拉；但还有一批零散硬编码半径（grep 实测）：`2px:832`、`3px:1373/1797/1878/2760`、`4px:1339/1346/1817/2411/2430/2525/.row-btn/3138/3405`、`6px:400/426/1043/1103/1181/2346/2385`、`7px:2021/.tab-badge/2868`、`50%` 圆形 8 处。
- 容器几何（harness 实测）：`#view-tabs` 400×33 直角；`.view-tab` 67×32 直角；`#tree`/`#results`/`#recent-list` 直角、`padding:3px 0`、inset shadow `0 4px 4px -4px`。
- tab 现状：`.view-tab` 无圆角、hover 平铺背景、选中仅 accent 文字 + `.tab-indicator` 2px 滑动条（`neat.css:1949-2038`）。
- 主题块：`:root`(light) + `body[data-theme=dark]` + `@media` auto 映射 + `ink` + `paper`（`neat.css:21-158`）；主题特有非 token 规则仅 2 组（favicon brightness `:635-642`、highlight-unsynced `:1676-1687`），共 28 行 → 解耦成本低。

**【设计】半径分层 token（放 `:root`）**

```css
--vbm-radius-xs: 2px;   /* 徽标内部、小角标 */
--vbm-radius-sm: 4px;   /* 行内按钮 .row-btn、分段开关、chips、历史区 */
--vbm-radius: 8px;      /* 默认控制件：输入框、主按钮、菜单、对话框、toolbar */
--vbm-radius-lg: 12px;  /* 主容器卡片：视图面板 */
--vbm-radius-pill: 999px;/* 药丸：tab-badge、计数、圆形按钮 */
```

**收敛映射表**（逐行替换到 token，完整表见附录 A）：`3px→sm`、`6px→sm`（横幅/历史区）或按角色、`7px(2021/2868)→pill`、`4px(行内按钮/seg/chips)→sm`、`2px(832)→xs`、`50%→pill` 保留圆形语义。

**卡片式视图容器（D2 落地）**
- `#views` 升级为卡片：`margin: 0 4px 4px; border: 1px solid var(--vbm-border); border-radius: var(--vbm-radius-lg); background: var(--vbm-bg-elev); overflow: hidden;`（`overflow:hidden` 天然裁切内部滚动条圆角）。
- `#view-tabs` 与卡片同宽（`margin: 0 4px`），作为卡片上方的扁平轨道——搜索区 → tab 轨道 → 卡片三层层次，与顶部圆角控件形成「现代分割」。
- `#tree`/`#results`/`#recent-list` 背景改透明（卡片底色由 `#views` 提供），去掉 inset shadow（卡片边框取代其分隔作用）。
- **ink/paper 主题豁免**：保留各自主旨——ink 用 `--vbm-radius-sm` 卡片（更克制）、paper 保留纸张直感（radius-sm 或 0，不跟随 lg），在各自 themes 文件覆盖。light/dark 全量采用 lg 卡片。

**tab 质感重绘（N2 落地）**
- `.view-tab`：`border-radius: var(--vbm-radius)`；hover `background: var(--vbm-bg-hover)`（圆角背景）；选中 `color: var(--vbm-accent)` + `.tab-indicator` 滑动条保留 + 可选淡 accent 底 `background: color-mix(in srgb, var(--vbm-accent) 12%, transparent)`；`transition: background .15s ease-out, color .15s ease-out`。
- 不做弧形过渡：popup 400px / 6 tab ≈ 67px 每 tab，弧形过渡（两段 mask 曲线）在该宽度下不可见，且与卡片语言冲突；扁平圆角实现零 mask、键盘/焦点语义不变。

**CSS 解耦（N3 落地）**
```
css/themes/
  themes-light.css   # :root(light) token + auto 浅色映射 + favicon 亮度等
  themes-dark.css    # dark token + auto 深色映射(由 themes-auto 引用)
  themes-auto.css    # @media(prefers-color-scheme:dark) 映射层
  themes-ink.css     # ink token + 主题特有规则 + radius 豁免
  themes-paper.css   # paper token + 主题特有规则 + radius 豁免
  classic.css        # A1 的 classic 覆盖（依赖 light token）
```
- `neat.css` 删除 token 块与主题特有规则，`popup.html` 在 `neat.css` 后追加 `<link>`（`sync-styles.css` 保持独立）。
- `pages/options.html` 主题下拉据此联动（同一 token 变量，无 JS 改动）。

**【实施要点】** ① 先做 token 收敛（机械替换，`theme.test.js` 补 radius 契约：断言无 `border-radius:<5px 的 3px/6px/7px 残留`）；② 再做卡片化 + tab 重绘；③ 最后解耦（新建 `css/themes/`，逐步搬移）；④ 每次解耦跑全量 vitest + harness 冒烟。

**【验收】** ① `theme.test.js`：radius token 契约 + 5 主题（含 classic）应用契约；② `scrollbar-contract.test.js` 更新卡片裁切断言（`#views` overflow:hidden 后无横向滚动条、纵向正常）；③ harness `verify-scrollbars.js` 全矩阵通过；④ 截图套件补 `theme-light-card.png` / `theme-dark-card.png` / `theme-ink-card.png`（对照豁免）；⑤ 解耦后 popup/panel/options 零 console 错误（smoke.js）。

### A3. 默认书签图标 SVG 优化（✓ SVG 化本体已落地，4.1.0 只做折角优化）

**【现状定位】** **SVG 化已落地（4.0.2）**：`DEFAULT_BOOKMARK_ICON`（`icons.js:41-46`）16px 线稿「文档 + 右上折角」，`favicon-fallback.js` 像素指纹已替换 placeholder。折角 `polyline 9.33 1.33 → 9.33 5.33 → 13.33 5.33` 是**尖折角**，生硬——4.1.0 只优化这一处。**4.0.4 新增** favicon 反色服务（见 A13）：占位图已换 SVG 随主题走，反色只作用于真实 favicon <img>，与 A3 无耦合。

**【设计】** 优化折角为**平滑圆角过渡**，保持同一 16px 网格 / 1.5px 描边语言（与 FOLDER_ICON 的圆角笔画一致）。推荐两版候选（落地时截图对比）：
- **方案 A（推荐）**：折角保留，但把尖折角改为带小圆角的折线——将 `polyline` 拆为 `path` 加 `stroke-linejoin="round"` 已生效的基础上，把折点坐标下移 0.5px 使视觉上不再「刺」，并给折线加 `stroke-linecap="round"`。
- **方案 B**：顶部右角改为圆弧角（`path` 用 `A` 弧替代直角折线），更接近现代 app 图标的「圆角文档」。

改动只涉及 `icons.js` 的 SVG 字符串；**`favicon-fallback.js` 指纹逻辑不受影响**（指纹只匹配 chrome placeholder 位图，不匹配替换后 SVG）。

**【验收】** ① 无 favicon 站点（light/dark/ink/paper 四主题）替换图标渲染清晰、折角不刺眼；② `favicon-fallback.test.js` 全绿（指纹行为不变）；③ 截图：`diag-favicon` 系列重拍对比。

### A9. hover 按钮右缘对齐（统一右缘槽）

**【决策 D3】** **统一右缘槽**：每个列表视图的 `.vbm-row` 预留一个「右侧动作槽」，槽宽 = 该视图最大动作位 × 24px（20px 按钮 + 4px 边距）；**没有动作按钮的行也占等宽槽**，使所有行内容右缘在同一基线。hover 揭示沿用 `visibility`（槽恒占 → 零回流、零位移）。否决「hover 时动态左移常显按钮」主方案。

- **dupes 视图（主要问题）**：group head 行尾常占 24px（✓ 按钮，`visibility:visible`），而成员行尾只有 badge（`margin-inline-end:4px`，`keeper-radio` 在**行首**）→ 组头内容右缘（`right-24px`）比成员行（`right-4px`）内缩 20px。**不 hover 也可见**——组头 URL/计数列与成员行标题列右缘明显错位，是用户观察到「不对齐」的主场景。
- stats 视图：★（`stats-star` 20px+4px，`neat.css:3382`）与 ☆（`.row-btn` 20px+4px）均占 24px → 已对齐，无需改。

- 搜索历史：所有行都有 remove → 一致。

   - `#tree` 不加（树行无行级动作按钮；dead × 在 favicon 上、不占行右缘）。
3. 跨视图右缘基线：列表内容右缘对齐「窗口右缘 − 4~8px」基线（与 header `tool-btn` 右缘 ≈窗口−2px、视图 toolbar 按钮右缘一致）。

## 4. 横幅通知全面重构（upstash 远程公告层）

**【决策】** 进 4.1.0。保留现有固定 message 兜底（捐赠卡 / 风险横幅 / history 权限横幅不回归），**新增远程公告层**：Upstash Redis REST 拉取 → `storage.local` 缓存 → **拉取失败静默**。每版本发布前注册一条 update-note；支持临时通知推送。

**【现状】** 三类横幅文案全部是随扩展打包的 i18n 静态 message（`neat.js:225-261` 捐赠/v4-notice + `risk-banner.js` + `view-recent.js:87-95`）；**CSP 已放行 `connect-src *`**（`manifest.json:68-71`），`host_permissions <all_urls>`（`:59-61`）——fetch 外部端点无需新增权限。upstash 可行性零障碍。

**【设计】**

**Upstash 数据模型**（一个 key `vbm:announce`，JSON 数组）：
```json
[{
  "id": "2026-08-v410",
  "minVersion": "4.1.0", "maxVersion": "",
  "channel": "all",                 // all | popup | sidepanel | options
  "once": true,
  "dismissKey": "vbmAnnounce202608v410",
  "display": { "type": "banner", "priority": 1 },   // dialog | banner | toast
  "titleKey": "announceV410Title",  // 优先 i18n key（客户端 _m()）
  "textKey": "announceV410Text",
  "textFallback": { "en": "What's new in 4.1.0…" }  // 拉取兜底（无 key 时）
}]
```
多语言策略：**优先 i18n key**（`textKey`/`titleKey`，客户端 `_m()` 翻译，省流量、语言全覆盖）；新发布前把 key 随版本打进 `_locales`，远程只存 key + en fallback。

**拉取与缓存**：
- 触发点：**popup/sidepanel 打开时**（页面生命周期短，打开即拉）；不常驻 SW。
- 缓存：`storage.local` `vbmAnnounce` = `{ ts, etag, data }`。**TTL 6h**。用 Upstash 的版本 key 语义：另存 `vbm:announce-ver`（发布时自增），客户端存 `lastVer`；`lastVer !== 当前ver` 才重新 GET `vbm:announce`（避免每次开弹窗都拉）。
- fetch：`fetch('https://<db>.upstash.io/get/vbm:announce', { headers: { Authorization: 'Bearer <只读token>' }, signal: AbortSignal.timeout(4000) })`。**失败/超时静默**（catch 全吞，不影响使用）。
- 只读 token 内置风险缓解：Upstash 免费层限流（读放大有限）、数据无敏感、仅 GET。

**显示**：打开时读缓存 → 过滤（版本区间 `compareVersions`、channel、`once`+`dismissKey` 未弹过）→ 按 `display.type`：
- `dialog`：复用 `dialogs.js` AlertDialog（发布 note 场景）；
- `banner`：复用 risk-banner 式行内横幅（顶部，Tab-ring 可达、非箭头 rung——键盘模型 §7 约束）；
- `toast`：复用 `undo.toastAction`。
- `dismissKey` 写入 `storage.local`（once 语义）。

**发布流程**：维护者发布前 `scripts/announce.py`（或文档记录 curl）PUT 一条 message + 自增 `vbm:announce-ver`。临时通知 = 随时再 PUT 一条。

**【实施要点】** 新模块 `src/announce.js`（纯逻辑：fetch+缓存+过滤+展示调度，注入 store/chrome，可 vitest 直测）；`neat.js` 挂打开时触发；`_locales/en` 加 `announceV410Title/Text` 等；`scripts/announce.py`（发布工具）。

**【验收】** ① `tests/announce.test.js`：版本过滤、once+dismiss、TTL 命中、fetch 失败静默、显示类型分发；② harness smoke：注入一条测试 announcement → popup 打开显示；③ `i18n.py missing` 门禁通过。
