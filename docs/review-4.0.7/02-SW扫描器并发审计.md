# 4.0.7 死链视图——SW 扫描器并发与可访问性审计

前两份报告（`00-死链视图-审计报告.md`、`01-性能与视觉打磨.md`）聚焦视图层
（`view-dead.js`）的功能完备性、性能与视觉。本报告补审**镜像架构的另一半**——
驻留在 service worker 里的扫描 runner（`src/dead-scan-sw.js`），核对其在 MV3
冷启动、消息驱动、异步 setup 窗口下的并发正确性，并顺带补齐视图层一处 a11y
缺口。结论：发现并修复 1 处真实并发缺陷（re-entrancy race），补 1 处 ARIA
语义，2 条边缘 case 评估后保持现状并记录依据。

---

## 1. 扫描 runner 的并发模型回顾

`createDeadScanRunner()`（dead-scan-sw.js）把扫描从 popup 迁到 SW，页面用
fire-and-forget 消息驱动，状态经 `chrome.storage.local` 的 `vbmDeadScan`
live blob 回流。关键并发风险点集中在 `start()` 的一段**异步 setup 窗口**：

```
start() ──storageGet(SETTING_KEYS)──▶ getTree() ──▶ [gateProxy()] ──▶ launch()
         ↑                          ↑              ↑
      回调#1 守卫                 回调#2 守卫     回调#3 守卫
```

在 `session` 尚未被 `launch()` 创建之前，`session` 为 null。这个窗口内的消息
（cancel / 二次 start / resume）落到旧代码上有两条后果：

1. **cancel 空转**：`cancel()` 入口 `if (!session) return`——setup 窗口内 session
   尚未建立，取消被直接丢弃；等 `getTree`/`gateProxy` 回调回来，`launch()` 照常
   执行，"取消的扫描"仍然启动并写缓存，违反 item-10"取消 = 从未发生"语义。
2. **双启动互相覆盖**：冷启动 `resumeIfNeeded()` 触发 start（getTree 在途），
   随后一条 `resume` 消息又走 `resume()` 的 `!session` 分支再触发一次 start——
   两条 setup 链并行推进，各自 `launch()` 覆盖同一个 `session`/`results`，同一
   批书签被探测两次。

`launch()` 之后的并发已由 `session` 判空 + `session !== s` 丢弃正确防护；缺陷
只在"session 尚未建立"这段窗口。

## 2. 修复：generation counter

引入 `let gen = 0;`，`start()` 每次进入自增并捕获 `myGen`，三个异步回调
（storageGet / getTree / gateProxy.then）在入口处 `if (gen !== myGen) return`；
`cancel()` 的 `!session` 分支改为 `gen++` + `stopProxy()` + `dropBlob()`，主动
作废在途链。gateProxy 的 then 回调（`begin()`）被作废时额外 `stopProxy()`——因为
gateProxy 可能在作废前已把 marker-PAC 装好，不拆会泄漏代理会话。

修复后语义：

- **cancel 落在 setup 窗口**：`gen++` 让在途链在下一个守卫处退出，`dropBlob`
  清掉旧 live blob，扫描从不启动、不写 cache——"取消从未发生"成立。
- **二次 start/resume 落在 setup 窗口**：旧链被作废，只有最后一条链 `launch()`
  ，`session`/`results` 不被 clobber，书签只探测一次。

## 3. 可访问性补充：dead-mark-btn 的 aria-pressed

结果行与残留行的 ⚑ 标注按钮此前只有 `aria-label`（在 deadMark/deadUnmark 间
切换）与 `.marked` class 着色，但按钮是**切换态控件**——`aria-pressed` 缺失让
屏幕阅读器无法得知当前是否已标注。补上：

- 结果行：`aria-pressed="${marked}"`（随 marked 布尔序列化为 true/false）。
- 残留行（恒已标注）：`aria-pressed="true"`。

与 `aria-label` 的 deadMark/deadUnmark 文案切换互补，label 说动作、pressed
说状态，符合 WAI-ARIA toggle-button 模式。

## 4. 回归测试

`tests/dead-scan-sw.test.js` 的 `makeChrome` 新增 `asyncGetTree` 选项，把
`getTree` 回调延迟一个微任务，模拟真实 `chrome.bookmarks.getTree` 的异步 gap，
从而能在 setup 窗口内落消息。新增 2 例：

- **cancel 落在冷启动 resume setup 窗口**：`fetched === 0`（未启动）、
  `local[DEAD_SCAN_KEY]` 与 `local[DEAD_LAST_KEY]` 均 undefined（从未发生）。
- **二次 start 取代第一次（无双启动）**：`seen` 只含 b/c 两个未判定书签各一次
  （双启动会各 fetch 两次），cache 结果集为 11/12/13 三个 id。

两例在**未修复**状态下均会失败（cancel 例 `fetched` 变 1 且写 cache；双启动例
`seen` 出现重复 URL），证明是真回归而非"测了显而易见"。

## 5. 边缘 case 记录（评估后保持现状）

- **`pause()`/`resume()` 在 setup 窗口**：`resume()` 的 `!session` 分支已由本次
  gen 修复覆盖（作废在途链后按 blob 状态重启）。`pause()` 只在 `session &&
  !session.isPaused()` 时生效，setup 窗口内本就没有可暂停的运行；且
  `resumeIfNeeded()` 已尊重 blob 的 `paused` 态——冷启动时 paused 的 blob 会以
  `startPaused: true` 重建，不会被误恢复为 running。窗口极窄、语义自洽，不加额外
  防护。
- **`resumeIfNeeded` 的 STALE_MS 判死**：`Date.now() - old.ts > STALE_MS`
  （24h）时 live blob 视为尸体不续扫，已覆盖"SW 被杀后 blob 残留"的冷启动主
  路径；本次审计确认该路径不经过 `start()` 的 setup 窗口（直接 `if (!raw ||
  session) return`），无新增并发风险。

## 7. 结论

镜像架构的 SW 侧（`dead-scan-sw.js`）在 `launch()` 之后已有正确的并发防护，但
`start()` 的异步 setup 窗口存在 re-entrancy race：cancel 会被丢弃、二次启动会双
跑。以 generation counter 修复后，"取消从未发生"与"单实例扫描"两条语义在窗口期
内同样成立，并有真回归测试锁定。另补 dead-mark-btn 的 `aria-pressed` 补齐切换态
控件的可访问性。至此，4.0.7 死链视图（视图层 + SW 层 + a11y）审计闭环。
