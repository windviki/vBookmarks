# 4.0.7 死链视图——性能与视觉打磨

审计报告（`00-死链视图-审计报告.md`）之后，按"从性能和视觉效果看看还有哪里
可以打磨"的要求复核死链视图。结论：性能无真实瓶颈（数据量级下现有缓存与 O(1)
查找已足够），发现并移除 1 处冗余计算；视觉发现 1 处区块混淆，补分隔线。

---

## 1. 性能评估结论（核查后保持现状）

- **`pathOf`**：`id => pathMap[id] || ''` 是 O(1) 预计算查找，`pathMap` 在树重建
  时由 `buildPathMap` 一次性构建，非每次渲染递归。✓
- **`allResultRows()`**：结果行有 `cachedResultRows` 缓存，`invalidateResultRows()`
  在 lastScan / 树 join / 缓存 verdict 变动时失效。单次 `render()` 内多次调用
  （`resultRows`/`badge`/`markStatusCounts`）全部命中同一缓存，无重复计算。✓
- **`markedRows()` / `markStatusCounts()`**：在数据量级（书签判定数）下线性遍历
  成本可忽略；未加 memoize（复杂度和失效时机风险大于收益）。✓
- **`refreshOverlays()`**：每次标记变更全量重扫树 DOM 打 ⚑——语义上必须（标记
  状态要实时反映到树上），数据量小，不做局部增量。✓
- **工具栏空态**：`.dead-toolbar:empty { display:none }` 自动折叠无内容工具条；
  `.dead-start` 已带 hover 提亮 + focus 发光。✓

## 2. 性能打磨（1 项）：移除 persistMarks 冗余的 updateBadges

`persistMarks()` 原本在每次标记变更（toggle / mark-all / unmark-all /
mark-selected / onRemoved 清理）都调用 `views.updateBadges()`，但：

- **badge 与标记无关**：`badge: () => allResultRows().length`（view-dead.js:1760）
  只数上一次扫描的 dead+blocked 结果行，不读 `deadMarks`。标记-only 变更不可能
  改变该值 → 每次 toggle 都是一次无意义的徽标重算 + DOM 写。
- **历史沿革**：`4b90294`（tab 角标实时化）把 updateBadges 挂进 persist 时 badge
  语义尚与标记相关；后来 `f5ecc9c`/`2deb3a1`/`c4a64ef` 把徽标改为扫描判定数，
  钩子未撤，成为遗留冗余。
- **移除安全性**（逐调用点核对）：
  - toggle/mark-all/unmark-all/mark-selected（991/1015/1034/1174）：marks-only，
    badge 值不变 → 冗余。
  - onRemoved（1401）：被删 id 若在 `lastScan.results`，1410-1412 已单独
    `invalidateResultRows()` + `updateBadges()`；非扫描结果 → badge 本就不变。
  - badge 真正需要刷新的路径保留不动：扫描完成（1329）、清除扫描结果（1060）、
    onRemoved verdict 删除（1412）、激活后存储读取（1784）。
- **测试**：原断言"每次标记变更 badge +1"改为"marks-only 变更 badge 不刷新"
  （tests/view-dead.test.js，marks + overlay describe）。

## 3. 视觉打磨（1 项）：残留标注区块与结果列表分隔线

"全部"视图下，本次扫描判定结果列表与下方"过去标注"（残留）区块同为 `.vbm-row`
行，此前仅靠 head 斜体标题区分，区块边界不清晰——尤其是残留很多时，两段同构行
列表连在一起，用户难以一眼看出"哪些是本次判定的、哪些是过去遗留的"。

**修复**：`renderMarkedRows(rows, hasResults)` 带第二个参数——结果列表存在时给
head 加 `.after-results` class，CSS 画一条短分隔线
（`border-top + margin-top:12px + padding-top:8px`，宽度随 head 文本即元素宽度，
不是整宽）：

- **live / all 视图**（结果列表在上方）→ `after-results`，残留区块与结果列表视觉分开。
- **marked-only 视图**（无结果列表，head 紧跟工具栏）→ 不带该 class：再画线会与
  工具栏 `border-bottom` 叠成双线。

**测试**：全部视图 head 带 `after-results`、marked-only 不带（tests/view-dead.test.js
mark-status filter + sort describe）。
