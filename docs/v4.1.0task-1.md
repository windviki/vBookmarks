## 一、视觉精细化

### 1. classic 主题
- **原文**：classic light 不应采用圆角的搜索框和顶部按钮，应改贯穿式搜索框 + 浮动的两个按钮，有输入时追加浮动的清空按钮。
- **现状**：不存在独立的 classic 主题；「一键恢复经典界面」（`src/options.js:110-128`）只是关掉 v4 新功能（`paletteEnabled`/`quickAddEnabled`/`quickAddContextMenu`/`showToolButton`/`showViewTabs`），不改变圆角。搜索框当前是 `--vbm-radius:8px` token 圆角字段（`css/neat.css:270-284`）；清空按钮已是字段内浮层（`visibility` 切换，`neat.css:331-351`）。
- **方向**：以当前的light主题为基准，建立一个classic主题（暂时只有浅色这个模式）。classic主题和一键恢复经典界面不冲突，只是为了在视觉效果上更加贴近方正的就有界面（v3.x时代的样式），其中一个特点就是贯穿式的顶部搜索栏。我们现在增加的两个按钮也应该尽量照顾未贯穿式的搜索栏样式。为 classic 模式加一个 body 标记类，针对性覆盖 `#search-field`/`#quick-add-btn`/`#tool-btn`——搜索框去圆角、贯穿式通栏；收藏/工具两按钮浮动；输入态浮现清空按钮。

### 2. modern 主题 R 角迭代
- **原文**：四个主题 modern 迭代，R 角元素、主视图列表区是否圆角框、tab 重绘更具质感。
- **现状**：实际是 **5 个主题值**（auto/light/dark/ink/paper，其中 light 即 `:root` 默认、auto 只映射 dark，`neat.css:21-158`）。统一 token `--vbm-radius:8px`（`:41`）已覆盖搜索框/按钮/菜单/对话框/下拉，但仍有一批零散硬编码半径 2/3/4/6/7px（`:832,1373,1817,1878,2021,2868…`）；tab 条（`.view-tab`）与列表容器（`#tree`/`#results`）为直角。
- **方向**：light/dark至少应该modern化（类似vscode最新的modern UI），一大特点就是各类容器边界用R角圆角巨型进行分割，这样既可以保留顶部已经有圆角的搜索框和按钮，也可以将tab和下方视图容器往这个方向靠拢，整体会更具备协调感和现代感。ink/paper主题因为有特定的主旨，可以不必全量照收R角矩形的完整设计，具体要怎么处理，应该为每个主题设立单独的设计和样式。另外需要考虑neat.css的解耦，把通用部分留下，主题不同的地方按主题建立样式文件。modern化的一些想法：①收敛全部零散半径到 token；②主视图列表区圆角框——**待决策**（滚动容器圆角 + 背景裁切需配套处理）；③tab 条质感重绘（hover/active 态、过渡、选中指示），是否采用类似macOS/Chrome经典的带有弧形过渡的tab样式，但要整体考虑和其他区域的协调程度来定下来具体设计。

### 3. 默认书签图标 SVG 化
- **原文**：默认书签图标的 SVG 化。
- **现状**：**已落地（4.0.2）**——`favicon-fallback.js` 用像素指纹识别 Chrome 默认地球位图并替换为 `DEFAULT_BOOKMARK_ICON`（`icons.js:41-46`，currentColor 16px 线稿，右上折角），`brightness(1.5)` 滤镜已随 issue #56 删除（`neat.css:629-634` 注释），真实 favicon 不再过曝。**4.0.4 新增反色服务**：`favicon-fallback.js` + `neat.css` `.favicon-contrast-invert`，选项 `faviconContrast` 默认开——复用每 src 单次 canvas 采样，亮色主题偏白（lum>0.70）或暗色主题偏黑（lum<0.30）且近单色（sat<0.25）的图标 `filter: invert(1)`，MutationObserver 监听主题切换准实时重判。
- **方向**：优化 `DEFAULT_BOOKMARK_ICON` 右上折角为圆角过渡（保持 16px 网格 / 1.5px 描边语言）；反色阈值（0.70/0.30）可后续按反馈微调。

### 4. 其他可图标化的位置
- **原文**：其他可以采用图标的地方进行细化。
- **现状**：`icons.js` 已提供 FOLDER/DOCUMENT_CODE/DEFAULT_BOOKMARK/CHECK/STAR/STAR_FILLED/FLAG/TRASH/CHEVRON/VIEW_ICONS 全套 SVG；favicon 位图通道已由反色服务兜底（4.0.4）。仍无 CLOSE_ICON/EMPTY_ICON/TAB_GROUP_ICON/SESSION_ICON 独立常量（`#search-clear` 的 × 与 dead-indicator 的 × 是内联 SVG/文本，未抽常量）。
- **方向**：枚举仍依赖位图/文本的控件（菜单项、选项页按钮、关闭按钮、占位态、dead/blocked 状态标记），检查当前文本按钮是否需要配icon起到视觉上的均衡和清晰效果。对需要的地方逐位 SVG 化并统一线宽 1.5px 语言。

### 5. sync 标记与死链标记同现优化
- **原文**：sync mark 和死链标记同时出现的视觉优化。
- **现状**：`sync-indicator` 钉右下（`css/sync-styles.css:17-36`）、`dead-indicator` 钉右上（`neat.css:3217-3241`），对角不碰撞（`:3203-3204` 注释明示「never collide」），同款 `box-shadow` 晕环。同现时右上 × + 右下点仍可能显拥挤。右上和右下的图标中心位置、大小均不相同，考虑到右上的标记本身含有内部的❌，太小的化可能看不清除，因此现版本接受了当前大小不一致的设计，你需要从整体效果来进行打磨，并同时考虑 #6 里面两各标记场景。
- **方向**：微调同现间距/尺寸，保持对角错位 + 晕环一致；补同现态截图回归。

### 6. 死链标记两种场景区分颜色
- **原文**：死链标记的两种场景区分颜色。
- **现状**：列表行 badge 已区分——`.row-badge.dead`=`--vbm-danger`（红）、`.row-badge.blocked`=`--vbm-warning`（琥珀），`neat.css:2952-2960`，判定在 `view-dead.js:430-447`（双通道：直连失败但代理可达=blocked）。但 favicon 上的 × 覆盖层（`deadMarks` 用户手动标记）恒定 danger 红，不区分 blocked/dead。
- **方向**：把 × 覆盖层也按场景着色（blocked 用琥珀，统一 dead=红/blocked=琥珀的语义），全部标记的化自动区分场景应用不同标记，已经筛选的情况下按实际场景进行标记。

### 7. 选项页精细化
- **原文**：选项页面的精细化——按钮样式、字体、动态排版等。
- **现状**：11 个分组（`pages/options.html:17-156`）；按钮已 token 化（`css/options.css:472-485`，`font:inherit`）；字体 `message-box`/14px；多列卡片走 CSS multicol `columns:340px`（`options.css:440-453`），4K 最多 5 列。
- **方向**：按钮 hover/active/focus 态打磨；排印微调；动态排版与主弹窗视觉语言对齐。

### 8. 最近搜索上部区域视觉优化
- **原文**：最近搜索上部区域目前有点拥挤。
- **现状**：`#search` 底距仅 4px（`neat.css:259`）+ 历史区顶 padding 3px（`:2288`），头行 `2px 8px`/12px（`:2302-2317`），行内塞了查询词+结果数+相对时间+图标+hover ×（`.search-history-row`，`:2449-2552`），密度高。
- **方向**：纯 CSS 间距/呼吸空间调整（头行高、行内 gap、输入行与历史区间距）；HTML/JS 结构已稳定，改动集中在 `neat.css:2283-2335` 与 `.search-history-row` 系列。

### 9. hover 按钮对齐
- **原文**：hover 才显示的按钮，不 hover 时整行右侧与其他固定元素视觉上不对齐，是否应动态布局（比如默认不显示hover，但是按钮都对齐到最右，hover时候动态左移常显的按钮，右边显示hover按钮，也即hover时才不对齐。不一定该方案最优，希望你综合所有帮我提供一个更好的方案）。
- **现状**：`.row-btn` 用 `visibility`（非 opacity）+ 固定 20×20 + 4px 槽位（`neat.css:2521-2537`），布局槽恒占不 collapse——不 hover 时空间保留。dupes keeper-radio 恒显；死链 × / 统计 ☆ 是 hover 揭示。
- **方向**：**待决策**——核对用户观察到的「不对齐」具体场景（可能是 hover 揭示的 ×/☆ 与上方工具栏右缘，行尾固定 badge/path/time 的右缘对齐基准不同），统一右缘基线或固定预留槽。

### 10. 主题跟随系统/浏览器
- **原文**：主题跟随系统/浏览器。
- **现状**：`theme` 设置（auto/light/dark/ink/paper）→ `body[data-theme]`；`auto` 仅用 `@media (prefers-color-scheme: dark)` 映射到 dark 一份（浅色落 `:root`，`neat.css:76-101`），**不跟随 ink/paper**（`:106`「auto never maps here」）。应用点 `popup.js:10,12`。
- **方向**：明确范围——「跟随系统」二态已实现；「跟随浏览器」若指 Chrome 浏览器 UI 主题（`chrome.theme`）需评估权限与实现；**待决策**是否在 popup 内加一个快速主题切换入口（当前只在选项页）。

### 11. 不同行/栏之间的视觉对齐
- **原文**：某些近邻的两个区域，视觉上是挨在一起的，如果各自的左右边缘不一样，就同样是不对齐的；以此为例，需要打磨各个控件之间的 margin/padding，不要拥挤，尽可能整体和谐，拥有 calm 的感觉。
- **现状**：
  - **左缘**：树/搜索结果文本轴 = 16px 引导槽 + 20px 图标槽 + 4px 间隙 = 40px（`neat.css:536-553` 三槽契约）；列表视图（recent/search/dead/dupes/stats）复用 `.tree-item-link` 同契约。**已落地（4.0.4）**：去重组头/成员行与死链选择模式复选框补 8px `padding-inline-start`（`neat.css`），与工具栏/历史头 8px 内联槽一致；双行行（宽/面板）图标 18px/槽 22px/间隙 8px。
  - **右缘**：`.row-btn` 恒占 20×20+4px 槽（`neat.css`），hover 揭示不回流；但 **dupes 组头 ✓ 恒占 24px、成员行尾仅 badge（4px）**——组头内容右缘比成员行内缩 20px，不 hover 也可见（A9 已识别为跨行右缘基线漂移）；dead 行恒占 48px（flag+trash）；tree 无行级右缘槽 → 跨视图右缘整体不同。
  - **相邻区域**：搜索框/工具栏 `padding: 4px 8px` vs 列表容器 `padding: 3px 0`；视图 toolbar 与列表右缘、历史区头行（`2px 8px`）与行右缘的基线。
- **方向**：**左右缘各收敛为一个系统**——左缘统一「槽位契约」（引导槽+图标槽+间距 token），控制件（复选框/radio/chevron）共享同一 gutter；右缘统一「右侧动作槽」（`--row-action-gutter`，无动作槽的行也占等宽槽，根治跨行/跨视图漂移，见 ds A9）；相邻区域的 margin/padding 收敛到 token（如 `--vbm-gutter`），不挤不散、整体 calm。

### 12. 高亮，hover，dnd 指示器等状态的样式按照主题进行优化
- **原文**：比如 modern 主题下高亮的行的矩形框要不要全宽？要不要 R 角；paper 主题下要不要渐变；dark 主题又如何醒目但是和谐？
- **现状**：
  - 状态全部走主题 token：行 hover `--vbm-bg-hover`、行 selected/focus/active `--vbm-bg-selected`+`--vbm-fg-selected`、焦点环 `2px solid var(--vbm-focus-ring)`、闪屏 `--vbm-flash`（各主题已差异化，`neat.css:21-158`）。
  - **高亮行形状**：列表/树行 hover 与 selected 是**全宽平铺背景、无圆角**（`#recent-list ul li a:hover` 等），焦点环 `outline-offset:-2px` 贴边。
  - **dnd 指示**：drop 行 `#drop-overlay.bookmark` = `--vbm-fg` 3px 线 + bg 描边；drop 文件夹高亮 `#drop-overlay.folder` = `--vbm-flash` 底 + accent 边 + **硬编码 2px 半径**（`neat.css:827-831`）；拖拽幽灵 `#bookmark-clone`（mask 淡出、`--vbm-bg` 描边）。
  - 死链「开始扫描」药丸 hover = `brightness(1.08)`（4.0.4 新增，非主题 token 驱动）。
- **方向**：为状态样式建立**按主题的「状态语言」**——① 高亮行是否全宽/圆角随 A2 卡片化定夺：light/dark（modern）若做列表卡片则高亮可带 `--vbm-radius-sm` 圆角，保持整行延续则保留全宽平铺；paper 可给 hover/selected 加轻微暖色渐变（纸上感）；ink 保持克制的 `--vbm-bg-selected` 深蓝、hover 用更低透明度叠色。② dnd 指示收敛：drop 行线/folder 高亮的颜色与半径按主题覆盖（light 用 fg 线+阴影、dark 用亮边、ink 用磷光 accent、paper 用墨线），`2px` 半径收敛到 `--vbm-radius-xs`；配合 A2 的 `css/themes/` 解耦，状态规则按主题收口。

## 二、命令面板

### 1. 自定义指令放最上方
- **现状**：自定义命令固定排在全部内置之后（`src/palette.js:450-461`，注释「customs merge right after the built-ins — muscle memory」），自定义间按 useCount 排序。
- **方向**：加选项让自定义区可置顶；内置区保持表序不漂移。

### 2. 隐藏非自定义指令、靠记忆命令
- **现状**：无此开关（选项页只有整面板 `paletteEnabled` 总开关，`options.js:83`）；「记忆」基础只有自定义 useCount（`palette-commands.js:178-192`）+ 搜索历史 MRU（`search.js:65-75`）；**内置命令无使用统计**。
- **方向**：新增选项键；`palette.js render()` 过滤内置区；给内置命令补一套 useCount 跟踪（或复用自定义排序）。

### 3. 允许命令组（一个命令包含多个指令）
- **现状**：action 白名单无 macro/组类型（`palette-commands.js:45`，仅 open-url/open-url-group/view-preset/url-template）；「open-url-group」是把书签文件夹当 URL 组，语义不同。
- **方向**：新增 macro action（一次执行多个指令序列）+ 校验 + 执行器。属较大特性，**待决策**排期。

### 4. 允许引用已有命令 / 包含已有命令
- **现状**：无（`docs/palette-commands-design.md` §9 阶段 3 的 macro 未做）。
- **方向**：macro 内按名字引用内置或自定义命令（如「/add 再 /stats」），依赖 3 的 macro 骨架。

### 5. 内置命令：切换 popup / sidepanel
- **现状**：底层调用点已存在——`chrome.action.openPopup`（`background.js:214-223`）与 `chrome.sidePanel.open`（`:255-258`），但都仅供快捷键命令；无 palette 命令项、**无 runtime 消息通道**让弹窗/面板页触达 SW（`background.js` 无 `onMessage`）。
- **方向**：palette 命令 fn → `chrome.runtime.sendMessage` → `background.js` 加 `onMessage` 复用 open 路径；「回弹窗」走现有 `setPanelBehavior(false)` + toggle 语义（`panel-behavior.js:136-152`）。

### 6. 内置命令：显示全部 / 仅显示书签栏
- **现状**：`onlyShowBMBar` 设置（`options.js:39`）在 `tree-view.js:98` 是**启动常量**（非热读）；已有会话级 `showAllOverride`（`:102`）与 `onChanged` 重渲染路径（`neat.js:821`）。
- **方向**：命令项翻 `store.set('onlyShowBMBar',…)` 或设 `showAllOverride` → 触发 `getTree(generateTree)`；需把 tree-view 的启动常量改为运行时读取。

## 三、搜索栏与命令面板输入栏扩展

> **vim 化已否决**（v4.1.0 不做、也不作为未来方向）——vBookmarks 是「打开即搜索」模型，vim 的输入/命令模式切换会破坏现有语义；`hjkl`/`gg/G` 等键位映射收益低、与 type-ahead 前缀匹配和 CJK 输入法冲突。改为调研两个输入栏（搜索栏 `#search-input` 与命令面板输入栏 `#palette-input`）的**实用扩展**。

### 现状
- **搜索栏 `#search-input`**：fuzzy 子序列匹配（`fuzzy-core.js`，title/url 双通道、精度 tier 排序、`<mark>` 高亮，`fuzzy.js` 挂 `window.VBMFuzzy`）；搜索历史 MRU（`search.js:57-75`，含相对时间/结果数/清除全部，4.0.4 清空与代理移除等已统一红色语义）；Enter 打开首结果/聚焦、ArrowDown 分流结果/历史（`search.js`）；树内裸字母 = type-ahead 前缀匹配（`keyboard.js:510-564`）；omnibox 与 popup 共用同一 `fuzzy-core` 排序（`search-core.js`）。
- **命令面板输入栏 `#palette-input`**：slash 命令表（`PALETTE_RESERVED` 17 内置命令 + unique-prefix 匹配，`palette.js:277-280`）+ 自定义命令（`ACTION_TYPES`：open-url / open-url-group / view-preset / url-template，`palette-commands.js:45`）+ 平铺查询桥接行（`paletteCmdSearchInView` → 跳搜索视图）；每个命令至多一个别名；已规划 `/next-theme`、`/panel`、`/popup`、`/onlybar`、`/all`（ds B4/B5/A10）。
- **两者均无**：字段过滤语法、URL 直开、计算器、结果批量操作、作用域搜索。

### 方向（按「价值/成本」排，低成本项可入 4.1.0，中成本另立排期）

**搜索栏扩展：**
1. **字段过滤 token**（低成本，推荐入 4.1.0）：在 fuzzy 之前解析前缀 token——`site:域名`、`folder:名`、`title:`、`url:`、`#标签`、`dead:`/`blocked:`（复用死链扫描结果）、`visited:N`（复用 visit-stats）。非 token 部分照常 fuzzy。落地：`fuzzy-core.js` 保持纯函数，`search.js` 加 token 解析层 + `<mark>` 高亮适配。
2. **多词 AND 分段匹配**（低成本）：当前整串子序列匹配；拆词后各词独立子序列 + AND 合并（fzf v2 语义），精度更高、可读。
3. **搜索结果批量操作**（中成本，4.2.0+）：结果区进选择模式（复用 dead/dupes 的 checkbox 机制）→ 打开全部 / 复制全部 URL / 删除 / 移动到文件夹。低成本先行版：直接「打开全部」「复制全部 URL」两个按钮。
4. **作用域搜索**（中成本）：树中聚焦某文件夹时搜索限定其子树（结合 `#tree` 焦点上下文）。

**命令面板输入栏扩展：**
5. **URL 直开**（低成本）：输入 `https://…`/裸域名 → 直接打开（复用 open-url 语义），不等书签搜索。需校验 `URL_RE` 与命令表不冲突。
6. **计算器/单位转换**（低成本）：`= 12*8` → 显示结果；`3km in miles`。纯前端受控 eval（白名单运算），结果可复制。
7. **设置项快捷开关**（低成本）：`/toggle <view>`（dead/dupes/stats/recent 的 show* 开关）、复用 A10 `/next-theme`。
8. **剪贴板命令**（低成本，ds B6 已列）：`/copy title|url|path`（`clipboardWrite` 权限已有）。
9. **参数化快速创建**（中成本）：`/add <标题> <url>` 直填（复用 B3 的 `{{rest}}` 思路，不依赖 macro）。

> 具体取舍与落地设计见 [`v4.1.0task-1-ds.md`](v4.1.0task-1-ds.md) §3。
