## #62 — 树视图 tooltip 只剩 URL（v4.0 起）✅ 已修复（本地）

**报告**：v4.0 起树视图悬停书签，tooltip 只有 URL、没有标题。

**根因**（真实回归，精确定位到机制层）：

- 设计意图（v3.7 延续）：行内名称**被截断时** tooltip 变 `名称\nURL`，未截断只有 URL。判定依据 `<a>` 的 `scrollWidth > offsetWidth`。
- v3.7 CSS 省略号挂 `<a>` 上 → 长名称时判定成立。v4.0 行结构改 flex 三槽，截断移进内部 `<i>`（`flex:1; min-width:0; overflow:hidden`，css/neat.css:728）→ `<a>` 永不溢出 → `titled` 分支永不触发 → 全部树行 tooltip 停在 URL-only。

**修复（修订 3 重做）**：初版只恢复了"截断行加标题"的 v3.7 自适应语义——维护者二审确立**新方向：所有视图所有行悬停显示完整信息**。自适应机制（`adaptBookmarkTooltip`/委托监听/resize 拖尾重测）整体退役，改为**渲染期烘焙**：

- `tree-render.js` 新增 `buildRowTooltip({title, url, path, dateAdded, append})`——唯一构造器，一行一个事实、段内转义、末尾 append 供视图扩展（死链标记等已在用），未来元信息追加带标签行即可：
  ```
  标题
  https://…
  Path: Bookmarks Bar / Dev      ← 规范序，恒定
  Added: 2026/8/29 13:40         ← toLocaleString
  <append 行>
  ```
- **覆盖面**（逐点排查接线）：树视图书签行（nodeHtml 经快照 paths map O(1) 查路径 + `d.dateAdded`）、树视图**文件夹行**（此前根本没有 title 属性）、搜索书签/文件夹行、**🏷标签组视图** tab 行与已关闭记录行（共享构造器自动获得 标题+URL(+关闭时间 append)）、recent/staging 行、stats 行、dead 行、dupes 行。

**测试**：generateBookmarkHTML 全套格式断言重写（含 Added 行、pathLabel 槽）+ folder 精确断言 + 快照断言 + 双 map 新用例；tree-view 的 adapt 用例组随机制退役删除（70→60 例）。

**回复草稿（EN，未发）**：

> Confirmed — a real regression introduced in 4.0 (the truncation check that upgrades a row's tooltip was still measuring the row anchor, but 4.0's flex-row CSS moved the clipping inside the name element, so it could never fire). We went further than restoring it: **every row in every view now shows the complete info on hover — title, URL, folder path, and the date added** — baked in at render time. No setup needed — it ships enabled in **4.1.1**. Thanks for the report!

## #63 — 经常记不住上次滚动位置（v4.1.0 报告）✅ 已修复（本地）

**报告**：v4.1.0 经常无法记住上次滚动位置，重开弹窗回到顶部。

**根因（两个洞，v4.0 机制、4.1.0 大树场景放大感知）**：

1. **关闭竞态**：v3.7 滚动写同步 `localStorage.scrollTop` 从不丢；v4.0 存储迁移改 200ms 尾随 debounce 异步写 + pagehide 兜底，而 pagehide 在弹窗关闭路径不保证触发（store.js 注释自证）——"滚动→立刻点书签→关窗"必丢最后位置。
2. **视图切换抹零**：tree 注册缺 `persistScroll`，切走（display:none 归零）再切回直接回顶，且此后首次滚动把存储的深位置覆盖成近顶值。

**修复**：`store.js` `scrollTop` 同步 localStorage 影子（专用键 `__scrollTopLS`，init 影子胜出 + reconcile，set/remove/adopt 全维护）；`view-manager.js` tree 补 `persistScroll: true`。测试：影子 ×5 + 往返恢复 ×1。

**回复草稿（EN，未发）**：

> Confirmed. Two separate holes, both from the v4.0 storage migration: (1) the scroll position was persisted through a debounced async write that races the popup closing — the "scroll → click a bookmark → popup closes" flow loses the last position; (2) switching to another view and back reset the tree to the top. Both fixed — the position now shadows synchronously so a quick close can't lose it, and view round-trips restore the tree scroll. Works out of the box in **4.1.1**, nothing to enable. Thanks for the report!

## #64 — 打开即聚焦搜索框 / 搜索结果显示文件夹路径 / PayPal 链接

### (a) "Open with the search field activated" ✅ 已实施 → 4.1.1

搜索框 `autofocus` 一直存在，但启动时 tree-view 的 focusID 行重聚焦与 view-manager 的 focusSpot 恢复会抢回焦点。新选项 `focusSearchOnOpen`（默认关，sync 区）开启后两处让位、stale focusID 即刻清除；选项页 Search 组第一个复选框。

### (b-i) 重开弹窗后恢复的搜索结果丢路径 ✅ 真实 bug，已修复 → 4.1.1

**现象（维护者实测）**：会话内首次键入搜索，结果无论宽窄都带路径；关闭再开（rememberView 恢复搜索视图 + saved-query 恢复结果列表），行里只剩裸标题。

**根因（启动序竞态，确定性复现）**：`initSearch`（neat.js:602）**先于** `initTreeView`（:722）。saved-query 恢复在 initSearch 尾部同步执行 `search()` → 索引未建 → 注册**自己的** `chrome.bookmarks.getTree` 回调 #1；tree-view 随后注册回调 #2。**回调按注册序执行** → #1 先跑：建索引 + 渲染结果 → 此时 view-manager 的 pathMap 仍空（它只在 #2 的 `onTreeGenerated` 里填充）→ 行渲染 `views.pathOf(id)` 全部空串 → 裸标题 + tooltip 无路径。#2 稍后填好 map，但**没有任何代码重渲染已显示的搜索结果** → 症状固化。会话内键入时树早已加载 → 有路径，故只在重开时出现。

**修复（治愈式，不依赖回调次序）**：

- `view-manager.js`：`pathMapReady` 标记 + API `pathsReady()`（buildPathMap/setPathMap 置位）。
- `search.js`：renderResults 时 map 未就绪则记 `stalePaths`；新 API `refreshPaths()`——stale 且搜索态非空时重跑当前查询（复用 runHistoryQuery 的 explicit 语义绕过 searchAfterEnter 门）。
- `neat.js`：`onTreeGenerated` 在填完 path map 后调 `search.refreshPaths()` 治愈。

**测试**：治愈用例（先裸后愈 + 干净渲染不触发 + 非搜索态 no-op）×3 + `pathsReady` 翻转 ×1。

### (b-ii) 文件夹出现在搜索结果里 ✅ 独立选项已实施 → 4.1.1

**事实**：文件夹行**本来就在**搜索结果里（索引含 `isFolder`，`renderResults` 有 folder 分支渲染 `link-folder` 行；#46 已修过点击 → `revealInTree` 树中定位）。所以增量是开关，不是新能力。

**实施**：`searchShowFolders`（**默认开**，保持现状；sync 区）。关闭时在 **100 行截断之前**过滤掉文件夹行（隐藏行不占结果预算）。选项页 Search 组第二个复选框「在搜索结果中显示文件夹（点击定位到树中位置）/ Show folders in search results (click reveals the folder in the tree)」。

### (b-iii) 路径显示顺序：就近反转 → **选项化，默认不反转**（修订 3 定案）→ 4.1.1

**决策记录**：修订 2 曾全局翻转就近在先；修订 3 定案——反转**仅限各视图 meta 行**（行标签/第二行），做成选项 **`reverseItemPath`（默认关）**；**tooltip 恒为规范序**（根在先、不限深，即 4.1.0 原格式）。

**实施**（终稿：不限深）：`tree-render.js` 双格式——`formatPath`（规范序 `' / '`；默认与 tooltip 恒用）+ `formatPathLabel`（全链就近在先 `A < B < C`，**无深度封顶**——溢出交给与正序相同的 CSS 截断，被截的是远端祖先）；`buildPathMap`/`buildTreeSnapshot` 单趟产出双 map（`paths` + `pathLabels`）。view-manager `pathLabelOf(id)` 选项感知（关=规范序 / 开=就近式），`setPathMap(paths, labels)` 双参；search/recent/stats/dead/dupes 的 meta 槽与自组合行（`路径 · 时间`）全部改走 label 形态；generateBookmarkHTML 标签槽用 `meta.pathLabel ?? meta.path`。选项页 Views 组 `showItemPath` 下新增复选框「行路径就近文件夹在先显示（倒序）」。

**测试**：pathLabelOf 开关 ×1、generateBookmarkHTML pathLabel 槽 ×1、buildPathMap 双 map（深度截断断言迁至 pathLabels）×2、favicon-gallery 回归规范序。

**发布注意**：默认外观与 4.1.0 一致（不反转）——商店截图按默认外观无需为此重拍。
