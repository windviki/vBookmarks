## #62 — 树视图 tooltip 只剩 URL（v4.0 起）✅ 已修复（本地）

**报告**：v4.0 起树视图悬停书签，tooltip 只有 URL、没有标题。

**根因**（真实回归，精确定位到机制层）：

- 设计意图（v3.7 延续）：行内名称**被截断时** tooltip 变 `名称\nURL`，未截断只有 URL。判定依据 `<a>` 的 `scrollWidth > offsetWidth`。
- v3.7 CSS 省略号挂 `<a>` 上 → 长名称时判定成立。v4.0 行结构改 flex 三槽，截断移进内部 `<i>`（`flex:1; min-width:0; overflow:hidden`，css/neat.css:728）→ `<a>` 永不溢出 → `titled` 分支永不触发 → 全部树行 tooltip 停在 URL-only。

**修复**：`src/tree-view.js` `adaptBookmarkTooltip` 改量 `<i>` 几何。测试：8 个既有用例打点移入 `<i>` + 回归 ×2。

**回复草稿（EN，未发）**：

> Confirmed — a real regression introduced in 4.0. The truncation check that upgrades a row's tooltip from "URL only" to "title + URL" was still measuring the row anchor, but 4.0's flex-row CSS moved the text clipping inside the name element, so the check could never fire. Fixed; it ships in **4.1.1**. Thanks for the report!

## #63 — 经常记不住上次滚动位置（v4.1.0 报告）✅ 已修复（本地）

**报告**：v4.1.0 经常无法记住上次滚动位置，重开弹窗回到顶部。

**根因（两个洞，v4.0 机制、4.1.0 大树场景放大感知）**：

1. **关闭竞态**：v3.7 滚动写同步 `localStorage.scrollTop` 从不丢；v4.0 存储迁移改 200ms 尾随 debounce 异步写 + pagehide 兜底，而 pagehide 在弹窗关闭路径不保证触发（store.js 注释自证）——"滚动→立刻点书签→关窗"必丢最后位置。
2. **视图切换抹零**：tree 注册缺 `persistScroll`，切走（display:none 归零）再切回直接回顶，且此后首次滚动把存储的深位置覆盖成近顶值。

**修复**：`store.js` `scrollTop` 同步 localStorage 影子（专用键 `__scrollTopLS`，init 影子胜出 + reconcile，set/remove/adopt 全维护）；`view-manager.js` tree 补 `persistScroll: true`。测试：影子 ×5 + 往返恢复 ×1。

**回复草稿（EN，未发）**：

> Confirmed. Two separate holes, both from the v4.0 storage migration: (1) the scroll position was persisted through a debounced async write that races the popup closing — the "scroll → click a bookmark → popup closes" flow loses the last position; (2) switching to another view and back reset the tree to the top. Both fixed — the position now shadows synchronously so a quick close can't lose it, and view round-trips restore the tree scroll. Ships in **4.1.1**.

## #64 — 打开即聚焦搜索框 / 搜索结果显示文件夹路径 / PayPal 链接

### (a) "Open with the search field activated" ✅ 已实施 → 4.1.1

搜索框 `autofocus` 一直存在，但启动时 tree-view 的 focusID 行重聚焦与 view-manager 的 focusSpot 恢复会抢回焦点。新选项 `focusSearchOnOpen`（默认关，sync 区）开启后两处让位、stale focusID 即刻清除；选项页 Search 组第一个复选框。

### (b-i) 重开弹窗后恢复的搜索结果丢路径 ✅ 真实 bug，已修复 → 4.1.1

**现象（维护者实测）**：会话内首次键入搜索，结果无论宽窄都带路径；关闭再开（rememberView 恢复搜索视图 + saved-query 恢复结果列表），行里只剩裸标题。

**根因（启动序竞态，确定性复现）**：`initSearch`（neat.js:602）**先于** `initTreeView`（:722）。saved-query 恢复在 initSearch 尾部同步执行 `search()` → 索引未建 → 注册**自己的** `chrome.bookmarks.getTree` 回调 #1；tree-view 随后注册回调 #2。**回调按注册序执行** → #1 先跑：建索引 + 渲染结果 → 此时 view-manager 的 pathMap 仍空（它只在 #2 的 `onTreeGenerated` 里填充）→ 行渲染 `views.pathOf(id)` 全部空串 → 裸标题 + tooltip 无路径。#2 稍后填好 map，但**没有任何代码重渲染已显示的搜索结果** → 症状固化。会话内键入时树早已加载 → 有路径，故只在重开时出现。

**修复（治愈式，不依赖回调次序）**：

- `view-manager.js`：`pathMapReady` 标记 + API `pathsReady()`（buildPathMap/setPathMap 置位）。
- `search.js`：renderResults 时 map 未就绪则记 `stalePaths`；新 API `refreshPaths()`——stale 且搜索态非空时重跑当前查询（复用 runHistoryQuery 的 explicit 语义绕过 searchAfterEnter 门）。
- `neat.js`：`onTreeGenerated` 在填完 path map 后调 `search.refreshPaths()` 治愈。

**测试**：治愈用例（先裸后愈 + 干净渲染不触发 + 非搜索态 no-op）×3 + `pathsReady` 翻转 ×1。

### (b-ii) 文件夹出现在搜索结果里 ✅ 独立选项已实施 → 4.1.1

**事实**：文件夹行**本来就在**搜索结果里（索引含 `isFolder`，`renderResults` 有 folder 分支渲染 `link-folder` 行；#46 已修过点击 → `revealInTree` 树中定位）。所以增量是开关，不是新能力。

**实施**：`searchShowFolders`（**默认开**，保持现状；sync 区）。关闭时在 **100 行截断之前**过滤掉文件夹行（隐藏行不占结果预算）。选项页 Search 组第二个复选框「在搜索结果中显示文件夹（点击定位到树中位置）/ Show folders in search results (click reveals the folder in the tree)」。

### (b-iii) 路径显示顺序：就近在先（左）✅ 已实施 → 4.1.1（维护者拍板）

**决策记录**：三案（A 维持根在先 / B 就近在先+限深 / C 仅限深）中维护者选 **B 方向——"就近父级在左"**。

**实施**：`tree-render.js` 新增 `formatPath(ancestors)`：最近 3 级祖先就近在先 `A < B < C` 连接，更深处尾缀 ` < …`；`computePathMap` 与 `buildTreeSnapshot` 两处共用。效果对比：

- 旧：`Bookmarks Bar / Dev / Frontend`（窄弹窗右截断，先吃掉最有区分度的近端）
- 新：`Frontend < Dev < Bookmarks Bar`，深层：`Frontend < Dev < L3 < …`

**影响面**：所有消费 `pathOf` 的视图（search/recent/dead/dupes/stats/favicons-gallery）行标签与 tooltip 统一翻转；`<` 作为数据在各渲染点经 `htmlspecialchars` 转义。测试：tree-render 格式断言 + 新增深度截断用例、favicon-gallery 断言同步。

**发布注意**：路径标签是可见 UI——按发布流程 Step 1，**4.1.1 发版需重拍商店截图**（`scripts/screenshots/update-store-assets.sh`）。
