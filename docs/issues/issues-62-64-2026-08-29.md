## #62 — 树视图 tooltip 只剩 URL（v4.0 起）✅ 已修复（本地）

**报告**：v4.0 起树视图悬停书签，tooltip 只有 URL、没有标题。

**根因**（真实回归，且能精确定位到机制层）：

- 设计意图（v3.7 时代延续）：行内名称**被截断时** tooltip 变成 `名称\nURL`，未截断时只有 URL。判定依据是 `<a>` 自身的 `scrollWidth > offsetWidth`。
- v3.7 CSS 把省略号挂在 `<a>` 上（`#tree ul li a { overflow:hidden; text-overflow:ellipsis }`）→ 长名称时 `<a>` 真的溢出，判定成立。
- v4.0 行结构改成 flex 三槽（`.tree-item-link { display:flex }`），截断移进内部名称元素 `<i>`（`flex:1; min-width:0; overflow:hidden; text-overflow:ellipsis`，css/neat.css:728）。`<a>` 本身**永远不再溢出** → `titled` 分支永不触发 → 所有树行 tooltip 停在 URL-only。JS 逻辑（H2 改成 hover 按需触发）本身没错，错的是测量基准随 CSS 重构失效。

**修复**：`src/tree-view.js` `adaptBookmarkTooltip` 改量内部 `<i>` 的几何（无 `<i>` 的行保持 URL-only）。行为回到 v3.7 语义：截断行 tooltip = `名称\nURL`，未截断 = URL（行内已可读全名，不重复）。

**测试**：既有 8 个 tooltip 用例的几何打点从 `<a>` 移入 `<i>` 双打；新增 #62 回归 ×2（锚点不溢出而 `<i>` 溢出 → 组合 tooltip；两者都不溢出 → URL-only）。

**回复草稿（EN，未发）**：

> Confirmed — a real regression introduced in 4.0. The truncation check that upgrades a row's tooltip from "URL only" to "title + URL" was still measuring the row anchor, but 4.0's flex-row CSS moved the text clipping inside the name element, so the check could never fire. Fixed on our side; it will ship in the next release. Thanks for the report!

## #63 — 经常记不住上次滚动位置（v4.1.0 报告）✅ 已修复（本地）

**报告**：v4.1.0 经常无法记住上次滚动位置，重开弹窗回到顶部。

**根因（两个洞，都是 v4.0 机制、4.1.0 大树场景放大感知）**：

1. **关闭竞态**：v3.7 滚动直接写同步 `localStorage.scrollTop`，绝不丢。v4.0 存储统一迁移（store.js）后改为 200ms 尾随 debounce 的异步 chrome.storage 写 + `pagehide` flush 兜底——而 store.js 自己的注释（flush API 处）就记载着 "**popup pagehide is not guaranteed on close**"。主流程"滚动找到书签 → 立刻点击（弹窗关闭）"几乎必然在 debounce 窗口内关闭且无 pagehide → 最后位置丢失 → 重开回顶。这就是"经常"。
2. **视图切换抹零**：view-manager 的 tree 注册没有 `persistScroll`，切走（`container.hidden`，即 display:none，scrollTop 归零）再切回直接回顶；且此后第一次滚动就把 store 里的深位置覆盖成近顶值，污染下次重开。

**修复**：

- `src/store.js`：`scrollTop` 增加同步 localStorage 影子（专用键 `__scrollTopLS`，旧版本从未写过它——避免 v4 迁移时冻结的 legacy `localStorage.scrollTop` 复活抢位）。`set/remove/adopt` 全维护；init 时影子存在则覆盖 chrome.storage 镜像值并 reconcile 漂移。这是恢复 v3.7 级可靠性的唯一同步通道。
- `src/view-manager.js`：tree 注册补 `persistScroll: true`（与 recent 视图同机制：切走前读、切回后恢复）。

**测试**：影子 ×5（set 同步落影子/debounce 前；remove 清除；init 影子胜出 + reconcile；无影子保持 chrome.storage 值——防 legacy 复活；adopt 刷新）+ tree 视图往返恢复 ×1。

**回复草稿（EN，未发）**：

> Confirmed. Two separate holes, both introduced by the v4.0 storage migration: (1) the scroll position was persisted through a debounced async write that races the popup closing (the "scroll → click a bookmark → popup closes" flow loses the last position), and (2) switching to another view and back reset the tree to the top. Both fixed on our side — the position now shadows synchronously so a quick close can't lose it, and view round-trips restore the tree scroll. Ships in the next release.

## #64 — 打开即聚焦搜索框 / 搜索结果显示文件夹路径 / PayPal 链接

### (a) "Open with the search field activated" ✅ 合理，已实施（本地）

**背景**：搜索框的 `autofocus` 属性一直存在（popup.html/sidepanel.html），但启动时 tree-view 的 focusID 行重聚焦和 view-manager 的 focusSpot 恢复会在渲染完成后把焦点抢回"上次所在行"，用户感知就是"打开时搜索框没激活"。原始 Neat Bookmarks 也从不自动聚焦搜索框，所以这是**合理的新特性**而非回归。

**实施**：新选项 `focusSearchOnOpen`（默认关；sync 区设备无关偏好）：

- 开启后两处抢焦点让位（ctx 注入 `getFocusSearchOnOpen`），autofocus 自然生效、打开即可直接输入（输入自动切换到搜索视图）。
- stale `focusID` 即刻清除，防止书签事件触发的重渲染 `scrollIntoView` 到未恢复的行。
- 选项页 Search 组第一个复选框「打开弹窗时聚焦搜索框 / Focus the search box when the popup opens」。

**测试**：tree-view 门控 ×1（不聚焦、不加 .focus、无 1ms/4s 定时器、focusID 立即清）+ view-manager 门控 ×1（不偷焦点、focusSpot 置 null）。

**遗留**：41 个 locale 是 `[TODO:optionFocusSearchOnOpen]` 占位——**合入前必须跑 `python3 scripts/i18n.py translate --apply` + `verify`**（本环境无 VBM_LLM 配置）。

### (b) "Show folders path in search results" 🟡 功能已存在；格式改良待决策

**事实**：v4 task-2 §3.6 已实现——搜索结果行显示所在文件夹路径（选项 `showItemPath`，**默认开**）：窄弹窗内联 `.row-path`，≥480px/面板模式第二行弱化文本，tooltip 里也有 `标题\nURL\n路径`。报告人可能是关了该选项、或期待的是**就近优先**的方向。

**报告人的格式建议**：`child result < parent < grandparent`——**就近父级在先 + 限深**。

**现状格式**：`buildPathMap` 自顶向下 `' / '` 连接（"Bookmarks Bar / Dev / Frontend"），不限深。窄弹窗里 CSS 截断从右吃起——**恰好先截掉最有区分度的近端父级**，留下 "Bookmarks Bar / …" 这种噪音。报告人的直觉是对的。

**提案（未实施，等决策）**：`src/tree-render.js` `computePathMap` 一行改动：

```js
// 现状
paths[node.id] = ancestors.join(' / ');
// 提案：就近在先 + 限深 3（省略号标远端）
const tail = ancestors.slice(-3);
paths[node.id] = (ancestors.length > 3 ? '… / ' : '') + tail.reverse().join(' < ');
// 显示效果："Frontend < Dev" 或 "… < Frontend < Dev"
```

**影响面（为何不擅自实施）**：`meta.path` 是跨视图共享格式——search/recent/dead/dupes/stats 行标签与 tooltip 全走它，v4task-2 的设计文档、多个测试锁定格式、guide 截图都会牵动。这是设计语言变更，三个选项：

- **A. 维持现状**，回复指出功能已存在（showItemPath 默认开）+ 说明格式；
- **B. 全面切换**就近在先 + 限深 3（我的倾向：区分度信息在前，截断吃掉的是远端噪音；但要同步测试/文档/截图）；
- **C. 只做限深**不改方向（`… / Dev / Frontend`，改动最小）。
