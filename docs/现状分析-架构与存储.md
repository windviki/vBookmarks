# 现状分析：架构层（manifest / background / 存储 / sync / 设置页 / 测试）

> 调研日期：2026-07-17。只读分析，所有结论附 `文件:行号` 证据，关键结论已经实测验证。
> 本文是 vBookmarks 现代化演进分析的分维度文档之一，姊妹篇：
> 《现状分析-弹窗UI.md》《趋势调研-MV3平台与书签品类.md》《现代化演进总方案.md》。

## 1. manifest.json 配置审计

**权限**（`manifest.json:39-45`）：`bookmarks`、`tabs`、`favicon`、`storage`、`identity`。

- `identity` **完全未使用**：全仓 grep 无任何 `chrome.identity` 调用，纯摆设，应删（减少安装警告）。
- `tabs`：omnibox 回车打开 URL（`background.js:131-137`）和 popup 大量 `tabs.query/create/update`（`neat.js:1460` 等）；其中读 `tab.url`（`neat.js:1468`）确实需要 `tabs` 或 `activeTab`。
- `favicon`：配合 MV3 `_favicon` API（`neat.js:412`）。

**host_permissions `<all_urls>`**（`manifest.json:50-52`）：**当前无正当用途**。无 content_scripts、无 webRequest；唯一沾边的是 bookmarklet 执行路径 `chrome.scripting.executeScript`（`neat.js:1480-1484`）——但 manifest **没声明 `scripting` 权限**，且引用的 `content-script.js` 文件在仓库里不存在，该路径必然抛错。即：带着最宽的权限警告，却什么功能都没换来。`web_accessible_resources`（46-49）把 `_favicon/*` 暴露给 `<all_urls>` 是官方文档写法，但若仅扩展页自用可收窄。

**CSP**（53-55）：`img-src 'self' data:; default-src 'self'; style-src 'self'`。`style-src 'self'` 无 `'unsafe-inline'`，与"自定义 CSS"功能直接冲突——`neat.js:3074-3078` 用 `<style>` 元素注入 userstyle 会被 CSP 拦截。`img-src data:` 是必要的（advanced-options 图标预览用 `canvas.toDataURL()`，`advanced-options.js:34`）。

**omnibox**：keyword `"*"`（58-60）。**commands**：有快捷键声明——仅 `_execute_action`（Ctrl/Command+Shift+V，29-38），无其他自定义命令（如"聚焦搜索"）。

**其他可改进点**：

- `background.type: "module"`（25-28）但 `background.js` 是无 import/export 的 IIFE，module 声明无意义。
- `update_url`（7）是 MV2 自托管遗留（`http://clients2.google.com/...`，明文 http），CWS 分发下无效；`checkupdate.json` 同为此遗留（内容还停在 3.1）。`background.html` 是 MV2 残留死文件。
- `minimum_chrome_version: 88`（56）与 sync 功能依赖的 `folderType`/`syncing` 属性（Chrome 138+，见 `docs/bookmark-sync-changes.md:70`）严重不匹配。

## 2. background.js omnibox 实现

结构：IIFE + `chrome.omnibox` 存在守卫（`background.js:1-2`）。

- **ranking**（19-41）：先按 `title.indexOf(query)` 位置升序（未命中记 Infinity）；都未命中时用 `^q1.*q2` 前缀正则（22）；再退化为 `dateAdded` 倒序；`slice(0, 6)`。两个缺陷：① `vPattern` 带 **`g` 标志**且在 sort 比较器中反复 `.test()`（34-35）——`lastIndex` 状态污染导致同一查询结果不确定；② 比较器混合 indexOf/regex 两条不对称路径，非严格弱序，排序行为依赖引擎实现。url 命中（`bookmarks.search` 会匹配 URL）但 title 未命中的条目全落 Infinity 档。
- **debounce**（10-16）：250ms trailing debounce 包住整个 async listener（78、123）。注意 `suggest` 回调被延迟到搜索完成后调用，Chrome 对 onInputChanged 有响应超时，250ms+搜索耗时尚在安全区；竞态（旧响应覆盖新输入）由 debounce 天然规避。
- **渲染**：`xmlEncode`（52-56）转义 5 个 XML 实体（omnibox description 是 markup 语境，必须）；`matcher`（58-69）把 query 按空白拆成 `a|b` 正则做 `<match>` 高亮；首条结果进 `setDefaultSuggestion`（101），其余进 `suggest`（113-118）。try/catch 有兜底（119-122）。
- **sync glyph**（71-76）：读 `bookmark.syncing`（Chrome 138+ 新属性），`undefined` 时不显示——老版本安全降级；☁=synced / 📁=local。
- **致命 bug**：第 93 行 `const firstResult = rankedResults.shift()` **遮蔽**了 44 行的外层 `let firstResult`；外层变量永远是 `null` → `onInputEntered`（125-138）里 `!firstResult` 恒真、提前 return → **回车永远不会打开任何书签**，omnibox 的核心动作完全失效。这是 MV3 重写时引入的回归（原 Neat Bookmarks 写的是全局变量）。
- **SW 生命周期坑**：模块级状态 `omniboxValue`/`firstResult`（43-44）在 SW 休眠回收后丢失——omnibox 会话极短所以实际影响小，但属反模式；`resetSuggest()` 顶层执行（50）每次冷启动重复 `setDefaultSuggestion`，无害但多余；`onInputEntered` 未接 `disposition` 参数，无法区分 Enter / Alt+Enter（新标签），永远 `tabs.update` 当前页（131-137）。

## 3. 设置存储现状

**storage.js API**：`StorageManager` 类提供 `getSetting`/`setSetting`/`getAllSettings`/`removeSetting`（19-74），`storage.get({[key]: default})` 注入默认值，错误一律 `console.warn` 静默吞掉。

**重复代码——比文档说的更严重**：1-87 行与 89-176 行是两份完整拷贝，且两份都顶层声明 `class StorageManager`（6 与 94）。作为经典脚本加载时这是**解析期 SyntaxError**（已用 `node --check storage.js` 实测：`Identifier 'StorageManager' has already been declared`）。即**整个文件根本无法执行**，`window.storageManager/getSetting/setSetting` 全不存在。旧文档所谓"第二份生效、侥幸可用"是错的。连带 `popup.js`（9 行处即调 `getSetting`）和 `options.js`（26）初始化全崩。这是当前仓库的头号致命回归。

**localStorage vs chrome.storage 混用全貌**：

| 存储 | 写入方 | 读取方 |
|---|---|---|
| chrome.storage.local（经 storage.js） | options.js 9 个 general 开关（26-31）、zoom（102）；popup.js popupHeight/Width（9-21） | 几乎没人读——**分裂脑** |
| chrome.storage.sync | options.js 3 个 sync 开关 + 刷新间隔（44-84，useSync=true）；sync-manager.js 直读写（37-52，不经 storage.js） | sync-manager.js 自己 |
| localStorage | neat.js 97 处（opens、dontRememberState、showSyncStatus、popupHeight、zoom、searchQuery、scrollTop、focusID、donation 系列、userstyle、customIcon、separator*）；advanced-options.js 全部 20 处；options.js 的 autoResizePopup 块（87-91） | neat.js（全部 UI 行为） |

**分裂脑是系统性的**：options.js 把 `leftClickNewTab`/`dontConfirmOpenFolder`/`onlyShowBMBar`/`searchAfterEnter` 等写入 chrome.storage.local，而 neat.js 全部从 localStorage 读同名 key（`neat.js:805、955、1455-1456、1759-1760、382`）——**设置页开关对弹窗完全无效**。sync 开关同理：写 sync 存储（options.js:48），neat.js 读 `localStorage.showSyncStatus`（`neat.js:436、469、3139`），neat.js:3219-3221 还在给 localStorage 版本设默认值。唯一"碰巧能用"的是 autoResizePopup，因为它被双写（generalSettings 数组 options.js:20 + 独立 localStorage 块 87-91，后者才是 neat.js:1169 读的那份）。另外**没有 localStorage→chrome.storage 的迁移代码**，老用户升级即丢设置。

**sync 配额风险**：当前 sync 只有 4 个小 key，字节配额（8KB/项、100KB 总量）无忧；但 `sync-refresh-interval` 的 `input` 事件**每次击键**都 `setSetting` + `syncManager.saveSettings()`（options.js:70-85）双写且无防抖，快速调整时有触发写频率配额（120 次/分钟、1800 次/小时）的风险。值模型也混乱：options.js 存 `'1'/''`（general）和 `'true'/'false'`（sync）字符串，sync-manager.js 却当 boolean 消费（38-43）。

## 4. sync-manager.js 评估

职责：sync 状态缓存（Map + 5 分钟 TTL，8-9）、7 类书签事件监听（55-63）、删除 undo 栈（10、70-82、149-185）、定时自动刷新（187-212）、统计/报告导出（369-443）、UI 指示器（446-495）。

- **同步状态判定**：`getSyncStatus`（265-305）优先用 Chrome 138+ 的 `node.syncing`（286-288），否则回退 `isBookmarkSynced`（307-312）——该回退只是"URL 不是 chrome:// 就算 synced"，语义错误。`folderType` 仅用于 tooltip 文案（482-484）。`canSync` 判定（294-301）中 `isUrlSyncable`（314-328，黑名单 8 种 scheme）与 `isSynced` 概念被混置。
- **undo 栈**：`onRemoved` 存 `removeInfo.node`（72-76），上限 10（78-80）；`undoLastDeletion`（149-185）只重建单节点，**文件夹子树无法恢复**（176-177 注释自认）；失败回栈（182）。栈在 popup 页面内存里，popup 一关即丢。
- **自动刷新名存实亡**：`SyncManager` 在 **popup 页的 DOMContentLoaded** 实例化（521-523），popup 关闭页面销毁，`setInterval` 随之死亡（191-194）——"每 60 秒自动刷新"只在 popup 开着时存在。正确归属是 service worker（配 `chrome.alarms`）。
- 其他质量问题：`processBookmarkTree`（231-246）对树中每个带 syncing 属性的节点发起一次 `chrome.bookmarks.get`，N 次 API 往返；`updateTreeSyncStatus` 全树串行 await（248-263），大树很慢；`invalidateRelatedBookmarks`（124-138）回调式调用不查 `lastError`；`notifySyncStatusChanged` 用 `window.dispatchEvent`（364）只能页面内通信；`module.exports` 守卫（526-528）在浏览器是死代码、在 Node 里 require 又会执行 `document.addEventListener` 而崩——两头不讨好。
- 加载面断裂：只被 `popup.html:107` 加载；`options.html` **没有**引入它，导致 options.js 里所有 `if (window.syncManager)` 分支（50、75）恒为死代码；`window.opener.neat.refreshSyncIndicators()`（options.js:62）对独立标签页打开的 options_page 也基本不触发。

## 5. 两个设置页

**options.html/options.js**（常规设置）：9 个 general checkbox + 3 个 sync checkbox + sync 刷新间隔数字框 + zoom 数字框（options.html:17-38）。**数据驱动**方式：`generalSettings` 数组（options.js:11-21）声明 `{id, key, defaultValue, inverted}`，循环读 `getSetting`→写 `checked`，change 时写 `'1'/''`（24-32）；`inverted` 处理"勾选=禁用"类选项（16-17）。syncSettings 数组（35-39）同构但存 `'true'/'false'` 到 sync 存储。i18n 标签全部在 JS 里 `innerText` 赋值（113-135）而非 HTML 内联。粗糙处：zoom 用 **setInterval 每秒轮询**刷新输入框（94-96）；`window.onerror` 发 `chrome.runtime.sendMessage`（106-110）但**全仓没有任何 onMessage 接收端**。

**advanced-options.html/js**（高级设置，纯 localStorage 页，不引 storage.js）：

- 自定义工具栏图标：file input→FileReader→canvas 19×19→`chrome.action.setIcon(imageData)`（16-35）；像素数据 JSON 化存 `localStorage.customIcon`（27），恢复时 for..in 回填（31-33）。注意 MV3 的 `setIcon` **不跨浏览器重启持久**，而恢复逻辑在 neat.js:3102-3111（popup 打开时补设）。
- 分隔符定制：4 个文本框直存 localStorage（66-100）。
- 自定义 CSS：**vendored CodeMirror v2 时代 API**（`CodeMirror.fromTextArea` + `onChange` 配置项，advanced-options.js:104-108），每次击键写 `localStorage.userstyle`；注入端 neat.js:3074 与 CSP 冲突（见 §1）。
- 重置：`localStorage.clear()` + alert + reload（110-114）——**只清 localStorage，不清 chrome.storage.local/sync**；迁移后 general/sync 设置都在 chrome.storage，重置已不再完整。
- **遗留 API**：`advanced-options.js:117` 的 `window.onerror` 用 `chrome.extension.sendRequest`——MV3 已移除，触发时自身抛 TypeError（options.js:107 已改用 sendMessage，但同样无接收端）。

## 6. 测试现状

- `tests/` 仅 `utils.test.js`（89 行，2 个用例），vitest + sinon（package.json:9-12；sinon 实际未被 import）。
- **两个用例测的都是"复制品"**：debounce（tests/utils.test.js:33-39）和 rankBookmarks（55-77）的实现是在测试文件里**重新抄写**的，再把 `chrome` mock 挂到 global（4-23，被测函数根本不用 chrome）。文件注释（26-27）自认原因。讽刺的是 rankBookmarks 的复制品把 `vPattern` 的 `g` 标志 bug 也原样抄了过来——即使源码修了测试也不会红。
- **根本局限（架构性）**：`background.js` 是 IIFE（`(() => {`）不导出符号；`neat.js` 是 3229 行 IIFE monolith；`sync-manager.js` 顶层依赖 DOM——三者均不可 import，测试只能测抄写本，失去回归保护意义。无 vitest.config、无 CI、无覆盖率；`package.json` 版本（3.6.0）与 manifest（3.7）已漂移。

## 7. 按严重度排序的结论

1. **storage.js 解析失败**（重复声明 SyntaxError）——popup/options 当前全崩，P0。
2. **background.js:93 变量遮蔽**——omnibox 回车打开功能全坏，P0。
3. **存储分裂脑**：options.js 写 chrome.storage、neat.js 读 localStorage，设置页整体失效；需统一存储层 + 老数据迁移。
4. SyncManager 归属错误（popup 页面而非 SW/alarms）、undo 栈随页面消亡。
5. manifest 减重：删 `identity`、收窄/删除 `<all_urls>`、补 `scripting` 或删 bookmarklet 死代码、清 MV2 遗物（background.html、update_url、checkupdate.json）、对齐 minimum_chrome_version。
6. 测试架构：需先把核心逻辑抽成可导入模块，否则 vitest 形同虚设。
7. 遗留 API：`chrome.extension.sendRequest`（advanced-options.js:117）、无接收端的 sendMessage、CodeMirror v2、`<menu type="context">` 等非标元素（popup.html:24 等）。
8. 打包脚本缺口：`scripts/package.py` 漏打 `storage.js`/`sync-manager.js`/`sync-styles.css`，且不排除 `node_modules/`——发版即事故。
