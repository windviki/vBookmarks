## 0. 决策框架

### 0.1 版本主题

**4.1.0 = 「视觉成熟」版本**。功能面只做三类高价值低成本项（内置命令补全、输入栏实用扩展、独立大屏页、远程公告），主力工程量投向视觉系统的**体系化**：把 4.0 以来零散打磨的成果（三槽契约、danger 语义、双行图标节奏、焦点律）收敛为一套**有名字、有不变量、可契约测试的设计语言**，并以此语言完成 classic 主题、卡片化、tab 重绘三个视觉里程碑。

## 1. 视觉语言总纲（本版本的「设计宪法」）

> 本章是全版本的定调文件。后面每条 A 系列设计都从这里推导；编码时凡与本章冲突的旧写法，以本章为准收敛。

### 1.1 一句话身份

**vBookmarks = 仪器感的专业工具**。五个主题各有性格（light/dark 是 Chrome 原生材质、ink 是示波器台面、paper 是仪表盘、classic 是老仪器方壳），但共享同一套**骨架不变量**：4px 基准网格、三平面深度模型、同心圆角律、制表数字、语义色只做语义。4.1 的「现代化」不是换个圆角，而是把这五条不变量从隐性变成显性 token + 契约测试。

### 1.2 三平面深度模型（canvas / surface / overlay）

卡片化（R1）的根基。全 UI 只有三个深度平面：

| 平面 | token | 用途 | light | dark | ink | paper | classic |
|---|---|---|---|---|---|---|---|
| **canvas 画布**（窗口底） | `--vbm-canvas`（新） | body 背景、搜索行与卡片的留白区 | `#f6f7f9` | `#141518` | `#0a0d13` | `#efe9dc` | `#ffffff` |
| **surface 表面**（卡片/控件） | `--vbm-bg`（行面）、`--vbm-bg-elev`（浮层） | 视图卡、搜索框、菜单、对话框 | `#ffffff` | `#26282c`（卡片可微调，见 §2.2.2） | `#171c28` | `#fffdf7` | `#ffffff` |
| **overlay 覆盖** | scrim + shadow token | 菜单/对话框/提示的投影 | 见 1.6 | | | | |

规则：
- `--vbm-bg` 语义微调为「**行所在表面**」（列表行、hover/selected 叠色、标记晕环都引用它）；`--vbm-bg-elev` 是「**浮起表面**」（菜单/对话框/下拉，永远盖在卡片之上）。行面与浮层面分离后，卡片色与菜单色可以独立调。
- **body 与大面积留白一律 `--vbm-canvas`**；卡片、输入框、菜单、对话框一律 surface。禁止再出现「白色卡片浮在白底上」。
- 标记晕环（sync 点 / dead × 的 `0 0 0 1.5px` ring）现引用 `--vbm-bg`——卡片化后行在 surface 上，晕环跟随 `--vbm-bg` 即自动正确（卡片就是行面），无需改。
- classic 主题 canvas = surface = `#ffffff`：平面坍缩为一张纸，这正是 v3 的视觉。

**迁移要点**：当前 `body { background-color: var(--vbm-bg) }` 改为 `var(--vbm-canvas)`；逐个检查引用 `--vbm-bg` 做「页面底色」的规则（预计仅 body 与个别全宽容器）改为 canvas。滚动条 thumb 颜色不变（叠在 canvas 与 surface 上都可读）。

### 1.3 4px 基准网格（发现并固化既有不变量）

实测当前所有行/槽/距指标**已经是 4 的倍数**：行高 28、缩进步进 24、图标槽 20、间隙 4、gutter 8、文本轴 40、动作槽 24、双行行 18/22/8（8 的倍数网）。4.1 把它写成规则：

- 一切间距、槽位、行高、内边距取 `4px × n`；例外仅允许：1px 边线/分隔线、2px 指示条/焦点环、焦点环偏移、以及**行内 1.5px 图标描边**。
- 新增间距 token（见附录 A）：`--vbm-space-1: 4px`、`--vbm-space-2: 8px`、`--vbm-space-3: 12px`、`--vbm-shell: 6px`（**唯一非 4 倍数例外**：弹窗外缘留白，6px 是 400px 宽下「有空气又不浪费」的实测甜点，明文豁免）。
- **契约测试**：`tests/design-system.test.js`（新）扫 neat.css 的 `padding/margin/gap/height/width` 声明值，白名单外的非 4 倍数即失败（对存量违例先登记豁免清单，随清理减表）。

### 1.4 半径阶梯 + 同心圆角律

```css
--vbm-radius-xs: 2px;     /* 状态指示条、dnd 线、徽标内衬 */
--vbm-radius-sm: 4px;     /* 行内控件：row-btn、seg、chip、行 hover/selected 背板 */
--vbm-radius: 8px;        /* 标准控件：输入框、按钮、菜单、对话框、下拉 */
--vbm-radius-lg: 12px;    /* 容器卡片：视图卡 */
--vbm-radius-pill: 999px; /* 计数药丸、圆钮 */
```

- **同心律（concentric radius）**：嵌套圆角满足 `内半径 = 外半径 − 内边距`。视图卡 lg 12 − 卡内 4px 边距 = 控件 8 ✓。规则写进 §1 的宪法，新增嵌套结构时校验。
- **半径阶梯可被主题整体覆写**——这是 classic（R3）与 ink/paper 分级的机制：light/dark 用默认阶梯；**ink** 覆写 `--vbm-radius-lg: 8px`（仪器克制）；**paper** 覆写 `--vbm-radius-lg: 4px; --vbm-radius: 4px`（印刷切块感）；**classic** 全阶梯归零。主题文件只改 5 个变量，零逐元素覆盖。「圆角阶梯随主题性格递减」成为可讲述的设计叙事。
- 收敛映射表（现存硬编码半径 → token）见附录 B；收敛后契约测试断言 neat.css 中不存在裸 `border-radius: 2/3/6/7px`。

### 1.5 排印与数字

- 字号三档 token 化：`--vbm-text-sm: 11px`（meta/徽标）、`--vbm-text-md: 12px`（历史头/工具栏/次级）、正文沿用 `font: menu`（~13px）。不引入更多档位——弹窗里每多一档就多一处不一致。
- **一切数字（计数药丸、结果数、相对时间、统计 count）`font-variant-numeric: tabular-nums`**：当前仅 3 处在用（neat.css 搜索 `tabular`），扩到所有 `.tab-badge`、`.row-badge`、`.history-meta`、`.history-time`、stats 计数、dupes 计数。数字列不再随位数抖动——仪器感的关键细节。
- CJK 标点悬挂不做（浏览器默认即可），但标题省略号维持现状 `text-overflow: ellipsis`（滚动条契约的一部分，不可动）。

### 1.6 深度与投影

- 卡片**不用投影**：1px `--vbm-border` 发丝线 + 平面色差（canvas vs surface）完成分隔——平面色差是主分隔手段，边线是辅助，投影只属于 overlay。
- 投影两档 token：`--vbm-elev-1: 0 2px 8px var(--vbm-shadow)`（菜单/下拉）、`--vbm-elev-2: 0 8px 24px var(--vbm-shadow)`（对话框/命令面板）。替换现存 ~20 处散写 box-shadow 中的浮层类（晕环、纯装饰类不动）。

### 1.7 动效语言

- 两档时长：`--vbm-dur-1: 120ms`（hover/按下/指示条）、`--vbm-dur-2: 180ms`（浮层进出、视图切换淡入）；统一缓动 token `--vbm-ease: cubic-bezier(0.2, 0, 0, 1)`（快出慢停，仪器阻尼感）。
- 全局 `@media (prefers-reduced-motion: reduce)` 收口为一条通配（现有散点规则合并）：`* { animation-duration: 0.01ms !important; transition-duration: 0.01ms !important }`。
- 动效只做「状态到状态的引导」（指示条滑动、浮层淡入），不做位移编排——工具不做秀。

### 1.8 状态语言（按主题）

每主题在主题文件给一组状态覆盖（`--vbm-bg-hover`/`--vbm-bg-selected` 已有，新增 dnd 语义色）：

| 主题 | hover | selected/focus | dnd drop 线 / 文件夹高亮 |
|---|---|---|---|
| light | 现状 `rgba(0,0,0,.05)` | 现状 `#d3e3fd` | fg 线 + 文件夹 `--vbm-flash` 底 + accent 边（现状），半径 xs |
| dark | 现状 `rgba(255,255,255,.07)` | 现状 `#2c3f5e` | 亮边线（`--vbm-fg-selected`） |
| ink | 现状靛蓝低透明叠色 | 现状 `#26314f` + **外发光** `box-shadow: 0 0 0 1px rgba(139,156,255,.25)`（磷光语义） | 磷光 accent 线 |
| paper | 现状暖调 | 现状 `#efe2ca`（**不做渐变**——渐变会破坏「印刷油墨」的平面性，推翻 task-1 §一.12 的「paper 可给渐变」想法） | 墨线（`--vbm-fg` 70% 混合） |
| classic | v3 淡蓝 `#e8f0fe` | v3 强选 `#d3e3fd` + fg-selected | 与 light 同 |

- **行 hover/selected 背板带 `--vbm-radius-sm` 圆角**（卡片内的圆角背板，现代列表质感），全宽不缩进、零回流：圆角只画在背板背景上，行几何不动——钉住行对齐契约与滚动条契约不受影响。
- 焦点环统一律：可交互控件 `:focus-visible` = `2px solid var(--vbm-focus-ring)`，`outline-offset: -2px`，环随控件半径（`outline` 自动跟随 `border-radius`，无需额外处理；仅确认无 `overflow` 裁切）。
- 拖拽幽灵 `#bookmark-clone` 与 dnd 线的半径收敛到 `--vbm-radius-xs`；死链「开始扫描」药丸 hover 的 `brightness(1.08)` 改为 `--vbm-bg-hover` 叠加（token 驱动）。

### 1.9 语义色纪律

`--vbm-danger`/`--vbm-warning`/`--vbm-success` **只用于语义**（破坏性/警示/成功），永远不做装饰色；4.0.5 已完成 danger 收口，4.1 补：任何新组件选色先问语义，非语义用 accent/muted/border。契约测试（`list-view-parity.test.js` 扩展）维持。

## 2. 视觉精细化（A 系列）

> 现状描述以当前代码为准；ds 文档中的行号在 4.0.5 审计后有 ±40 行漂移，本文一律用**选择器锚点**定位。

### 2.1 A1 · classic 主题（第 6 个主题值）

**决策**：`theme` 增加 `classic` 值，`body[data-theme="classic"]`，仅显式选择（不参与 auto 映射，深色系统下仍显示浅色——classic 的承诺是「回到 2013 年的样子」，那年没有深色模式）。与「一键恢复经典界面」开关**正交**：开关管功能（palette/快加/tab 条等），主题管皮。

**现状核对**：主题应用点 `popup.js`（`document.body.dataset.theme = store.get('theme','auto')`），token 块在 neat.css 头部；搜索框为 `--vbm-radius` 圆角字段（`#search input`），`#search` 现有 `margin: 2px 2px 4px`；清空按钮已是字段内浮层（`#search-clear`，`visibility` 切换）。

**设计**（依赖 §1.2/§1.4 的机制，主题文件总行数预计 < 40 行）：

1. **半径阶梯归零**：
```css
body[data-theme="classic"] {
    --vbm-radius-xs: 0; --vbm-radius-sm: 0; --vbm-radius: 0;
    --vbm-radius-lg: 0; --vbm-radius-pill: 0;
    --vbm-canvas: #ffffff;          /* 平面坍缩 */
    --vbm-bg-hover: #e8f0fe;        /* v3 记忆色 */
    /* fg/muted/border/accent/danger… 全部继承 light（加载顺序保证） */
}
```
2. **贯穿式搜索栏**：`#search { margin: 0 0 0 0 }`（左右贴窗）；输入框边框加强为 `color-mix(in srgb, var(--vbm-fg) 40%, transparent)`（v3 强灰 inset 边）；搜索图标位置不变。
3. **按钮扁平化**：`#quick-add-btn`/`#tool-btn` 去 surface 底与边框，`background: transparent`，hover 直接 `--vbm-bg-hover`；「浮动」语义 = 按钮成组贴在贯穿式搜索栏同一行右端（现有 flex 布局即成，无需挪动）。
4. **卡片拍平**：`#view-tabs, #views { background: transparent; border-color: transparent }`；列表容器 inset shadow 移除。tab 条退化为 v3 式下划线 tab（指示条保留——v3 本就有蓝色下划线）。
5. 徽标药丸随阶梯归零变方——刻意保留，是「老仪器方壳」的一部分。

**实施**：`css/themes/classic.css`（依赖 light token，加载序在最后）；options 主题下拉加项 + `themeClassic` i18n；`store.js` theme 合法值列表（若有）加 classic；`/theme classic` 直选可用，**不进 `/theme` 列表循环的默认序首位**（列表里按字母序正常展示即可）。

**验收**：① classic 下搜索栏通栏方角、按钮扁平、tab/列表直角透明；② 与「一键恢复经典界面」四开关叠加无冲突（方壳 × 无 tab 条）；③ `theme.test.js` 补 classic 契约：全阶梯 0、canvas==bg、hover 色；④ shots-themes 加 classic 一版。

### 2.2 A2 · modern 化：三平面 + 卡片 + 附着式 tab + CSS 解耦

#### 2.2.2 视图卡片化（light/dark 全量，ink/paper 按阶梯递减，classic 拍平）

结构（CSS-only，无 DOM 改动）：

```css

    margin: 0 var(--vbm-shell);
    border: 1px solid var(--vbm-border);
    border-bottom: 0;
    border-radius: var(--vbm-radius-lg) var(--vbm-radius-lg) 0 0;
```

#### 2.2.3 附着式 tab 重绘（视觉签名）

「tab 长在卡片上」——具体语言：


- **指示条升格为「卡内插入条」**：`.tab-indicator` 从卡外底线（现 `bottom:-1px` 悬在 border 上）改为**卡内顶缘插入**——高度 2px、`--vbm-radius-xs` 圆头、位于 tab 条底边**内侧**，滑动动画保留（transform 150ms → 收敛 `--vbm-dur-1`）。选中 tab 的文字 accent + 8% accent 底 + 内插指示条，三者叠加构成「当前分页被抬起」的层次。

## 4. 输入栏扩展（C 系列）

> vim 化永久否决（沿既定结论）。以下为 4.1 落地的三项半。

### 4.1 C1 · 搜索栏字段过滤 token

**语法**：空格分隔；`key:value` 形态的词解析为过滤器（大小写不敏感），其余词进 fuzzy。六键：

| token | 语义 | 数据源 | 匹配 |
|---|---|---|---|
| `site:github.com` | URL host 含此串（host 等值或后缀，`github.com` 命中 `gist.github.com`） | 索引项 url | 小写子串/后缀 |
| `folder:工作` | 任一祖先文件夹标题含此串 | `views.pathOf` 路径映射（现成） | 大小写不敏感含 |
| `title:词` | 词只允许命中 title 通道 | fuzzy 索引 | 通道限定 fuzzy |
| `url:词` | 同上，限定 url 通道 | 同上 | 同上 |
| `dead:` | 仅显示死链扫描结果为 dead 的书签 | `deadLastScan.results` | status === 'dead' |
| `blocked:` | 仅 blocked | 同上 | status === 'blocked' |

**架构**：`src/search-tokens.js`（新，纯 ESM）：`parseSearchTokens(raw) → { tokens, fuzzyQuery }`；`applyTokens(items, tokens, ctx) → items'`（ctx 注入 pathOf/deadResults）。`search.js` 在调 `VBMFuzzy.rank` 前套用；`fuzzy-core.js` 不动（保持 omnibox 共用核心的纯度——omnibox 不启用 token，行为不变，parity 契约不破）。
**高亮**：`<mark>` 只标 fuzzy 词命中位；token 过滤不做标色（过滤是集合运算，不是命中指示）。搜索历史存原始串。空 fuzzy 查询 + 有 token = 纯过滤模式（结果按 dateAdded 降序）。
**i18n**：无新 key（语法不解释在 UI 上；文档写进 guide-v4 §3）。
**验收**：`search-tokens.test.js`（新）：解析/六键过滤/混合查询 `site:github.com work`/未知 token（`foo:bar` 按 fuzzy 词处理——**决策：宽容策略**，无冒号歧义则不报错）/大小写。

### 4.2 C2 · 多词 AND 分段匹配

**语义**（fzf v2 式）：查询按空白拆词，每词独立子序列匹配 title/url，**全部命中才入选**；排序 = Σ(词得分)（title×2/url×1 的既有权重逐词计）降序，tie → dateAdded 降序（沿现状）。`<mark>` 位 = 各词命中位并集。
**架构**：`fuzzy-core.js` 的 `rank()` 内部对多词拆分聚合（`score()` 仍单词——单词是组合单元）；`search-core.js` 的 `rankBookmarks` 包装自动继承 → **omnibox 同步获得多词 AND**（parity 契约扩展：两边同断言）。CJK 无空格查询不受影响（单词路径）。
**验收**：`fuzzy.test.js`——顺序不敏感 AND、任一词未命中即排除、多词分数聚合序、mark 位并集；`search-core.test.js` parity 扩展。

### 4.3 C3 · 命令面板三项扩展

1. **URL 直开**：平铺查询命中 URL 判定（`/^https?:\/\//i` 或裸域名 `/^[\w-]+(\.[\w-]+)+(\/\S*)?$/` 且含 `.`）→ 首位渲染「打开 URL」行（新 i18n `paletteOpenUrl` + URL 原文展示，行模板复用命令行样式 + 外链图标位）。Enter 开新标签。与命令表无冲突（slash 查询优先走命令路径，URL 形态必不以 `/` 开头）。安全：URL 经 `encodeURIComponent` 校验后交 `chrome.tabs.create`；`javascript:`/`data:` 形态不触发（正则天然排除）。
2. **`=` 计算器**：查询以 `=` 开头（`=` 后至少 1 字符）→ 首位渲染「结果」行。求值器 `src/calc.js`（新，纯 ESM，递归下降）：数字（含小数）`+ - * / % ^`、括号、一元负号、`e` 记数；除零/溢出/非法 → 结果行显示 muted「—」。Enter = 复制结果到剪贴板 + toast（i18n `paletteCalcCopied`）。**不用 Function/eval**（R5）。单位转换**不做**（语料与维护成本不成比例，砍掉 ds 的 `3km in miles` 想法）。
3. **`/copy`**：`/copy title|url|path`（默认 url）——作用于**当前焦点行**的书签（列表 `.focus` 行；无焦点行时作用于 palette 打开前的 opener 焦点行——`initPalette` 已保存 opener，复用）；无目标 → toast 提示。i18n `paletteCopyDone` + `paletteCopyNoTarget`。

**验收**：`palette.test.js`——URL 行置顶与形态判定（含 `javascript:` 拒绝）、计算器结果/异常/复制、`/copy` 三参；`calc.test.js`（新，~25 例含注入串）。

## 5. 远程公告层（D）

**决策**：进 4.1.0。保留三条本地横幅（捐赠/风险/history 权限）不回归；新增 Upstash REST 公告层，**拉取失败静默**。

### 5.1 数据模型（Upstash key `vbm:announce`，JSON 数组）

```json
[{
  "id": "2026-08-v410",
  "minVersion": "4.1.0", "maxVersion": "",
  "channel": "all",                      // all | popup | sidepanel
  "once": true, "dismissKey": "v410-note",
  "display": { "type": "banner", "priority": 10 },   // dialog | banner | toast
  "titleKey": "announceV410Title",       // 优先走客户端 _m()（43 语种零流量翻译）
  "textKey": "announceV410Text",
  "fallback": { "en": "What's new in 4.1.0 …", "zh": "…" }  // 无 key 时的兜底（键名用 Chrome UI 语言前缀匹配）
}]
```

- **安全边界**：`fallback` 是**纯文本**，渲染一律走 `escapeHtml`（`src/escape.js`）——远程内容永不 innerHTML 裸拼（4.0.5 注入审计的同一纪律）；不做远程 HTML、不做远程图标。`display.type` 只能取枚举三值，未知值丢弃该条。单条 `text` 长度上限 500 字符（超长截断），数组上限 10 条（取前 10）。
- **版本/渠道过滤**：`compareVersions`（`src/version.js` 现成）判 min/max；channel 按当前页面形态（popup/sidepanel；options 不参与 4.1）。

### 5.2 拉取与缓存

- 触发：popup/sidepanel 打开时（`neat.js` 启动尾异步触发，不阻塞渲染）。
- 缓存：`storage.local` `vbmAnnounce = { ts, ver, data }`；**TTL 6h**。请求序：`GET /get/vbm:announce-ver`（一次极小读）→ 与缓存 `ver` 相同且未过期 → 直接用缓存；不同/过期 → `GET /get/vbm:announce` 全量。每 6h 最多 2 个请求。
- fetch：`Authorization: Bearer <只读 token>` 内置于 `src/announce.js` 常量（只读 token 可公开；写 token 只存维护者 `.env`，仓库与扩展零出现）；`AbortSignal.timeout(4000)`；任何异常（网络/超时/解析/超限）**静默吞掉**并沿用旧缓存。
- 隐私注记：拉取会向 Upstash 暴露用户 IP/时间（每 6h 一次）；写入 docs/README 隐私段与商店说明。

### 5.3 展示调度

- 打开时读缓存 → 过滤 → 取 `priority` 最高**一条**展示（同开多 surface 排队不叠放）；与捐赠卡同帧出现时**捐赠卡优先**（本地体验优先于远程公告，公告顺延到下次打开）。
- `banner`：顶部行内横幅，复用 risk-banner 骨架（Tab 环可达、非箭头 rung——键盘模型 §7 约束）；`dialog`：AlertDialog；`toast`：`undo.toastAction`。
- `once` + `dismissKey`：关闭即写 `storage.local` `vbmAnnounceSeen`（数组，上限 100 条 LRU）；非 once 每次满足条件都显示（临时通知场景）。
- **展示总闸**：选项 `announceEnabled`（默认开；关闭 = 完全不拉取——隐私退出开关，也省流量）。

### 5.4 发布工具

`scripts/announce.py`（stdlib only）：`list` / `put <json-file>` / `del <id>` / `bump-ver`；凭据 `ANNOUNCE_UPSTASH_URL`/`ANNOUNCE_UPSTASH_WRITE_TOKEN` 从 git-ignored `.env`。发布流程文档并入 AGENTS.md Release Step 1。

**实施**：`src/announce.js`（fetch + 缓存 + 过滤 + 调度建议，注入 store/chrome/fetch —— vitest 直测）；`neat.js` 接线一行；`tests/announce.test.js`（版本过滤/once/TTL/静默失败/枚举校验/长度上限/纯文本转义断言——**转义断言是安全门，必测**）。
