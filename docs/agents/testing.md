**Test infrastructure (2026-08 audit round — use these in NEW tests):**

- `tests/helpers/dom.js` — `makeEl`/`makeClassList`/`makeStoreDouble`. The stub's initial state must mirror the real HTML/CSS defaults (a `hidden` attribute, `#donation { display:none }`): a mismatch produces false positives/negatives.
- `tests/helpers/i18n.js` — `makeI18n()` reads the REAL `_locales/en/messages.json` and substitutes the NAMED placeholders (`$count$` etc. → positional `$1`/`$2` via each key's `placeholders` table), so parameterized copy (confirm dialogs, toasts) is assertable; `makeI18nEcho()` keeps the key-echo form. The parameterized-copy contract is centralized in `tests/i18n-copy.test.js` (real replaced output per key) — en-copy wording changes fail there by design. Existing suites still use `key => key` echo doubles; migrating their assertions to real English copy is a deliberate, file-by-file task.
- `tests/helpers/chrome.js` — `makeStorageArea`/`makeBookmarksDouble` factories that record calls.
- `tests/helpers/boot.js` — `bootWithStubs()` for modules that auto-run `init()` at import (e.g. `options-palette-commands.js`). Trap: `vi.resetModules()` **wipes the special `location` global** (document/chrome/store survive) and a second import double-registers listeners on shared DOM stubs — import exactly once per test through this helper, which re-applies `location` and flushes.
- `tests/helpers/classic.js` — `loadClassicScript(source, window)` wraps the sandbox-eval `new Function` path for classic scripts (store/sort-utils/sync-manager — `tests/fuzzy.test.js` left this pattern in 4.0.5: it imports `src/fuzzy-core.js` directly), so a new suite doesn't hand-roll the eval.
- **Never copy the implementation under test into a test** — drive the real module; extract pure logic into a real module when it can't be imported (see "操作即模块" in Code Style).

Chromium launches with `--load-extension=/ext` and `headless: 'new'` (old headless does not load extensions). This caught two ship-blockers: `side_panel.default_path` rejects query strings, and `style-src 'self'` blocked all inline style attributes.

Two harness gotchas learned the hard way (v4 task-4): ① once a script opens tabs with `active: true`, the extension page becomes a background tab — `Runtime.evaluate` still answers there, but `page.click`/`page.screenshot` (anything needing layout) hangs until `protocolTimeout`; call `page.bringToFront()` before clicking again. ② The harness loads `popup.html` as a regular tab, and the actions layer's post-open `window.close()` (actions.js) would close that tab for real and detach the CDP frame — both scripts stub it via `page.evaluateOnNewDocument(() => { window.close = () => {}; })`. Relatedly: DinD has no outbound network, so seed test bookmarks with fast-failing URLs (`http://127.0.0.1:9/…`) — an external domain hangs the navigation and wedges the run. ③ Navigations in `smoke.js` use `waitUntil: 'load'`, never `'networkidle0'`: the extension's own background fetch chains (announce feed → GitHub mirror discovery, favicon enrichment, sync) can stay in flight past the 30 s navigation timeout in the offline sandbox, so a network-idle wait flakes the gate even though the page is fully ready — the post-navigation sleeps absorb the async init instead. ④ Seed harness storage by AREA (2026-08 storage audit): sync-routed keys (store.js SYNC_KEYS) must be seeded into `chrome.storage.sync` and cleaned from BOTH areas — a local-only remove leaves the sync copy alive and leaks state into later sections (this cost the smoke gate's dead-filter section: rememberView/showViewTabs '' leaked from the classic-chrome section and the dead view never activated). Seeds written to local still take effect via the store's local→sync migration on the next load, but repeated writes are ignored once sync owns the key. And a repo-file permission trap (4.0.8): runtime files created mode-0600 (`src/github-source.js`/`github-mirrors.js` were, once) load fine from the host disk but fail inside the image with `net::ERR_ACCESS_DENIED` — Chromium runs unprivileged there — which kills the whole ES-module graph (tree never renders, every post-reload check fails) while `npm run test:run` stays green.
