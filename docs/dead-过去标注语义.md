# Dead 视图"过去标注"分类语义

本文档定义死链视图（`src/view-dead.js`）"过去标注"分类的语义原则，作为实现与后续改动的规范。

## 1. 定义

- **`deadMarks`**（store key `deadMarks`，id 数组）：用户在死链视图通过 ⚑ / `M` 键 / 选择模式批量标记的书签 id 集合。它独立于扫描结果持久化，是"过去标注"的数据来源。
- **"过去标注"分类**：相对于一次新检测的"待定"集合——开始新检测时它是过去所有标注；随着检测逐条给出判定，被判定为死链/受限的标注实时流入对应结果分类。

## 2. 生命周期（一次新检测）

1. **开始新检测**：把过去所有标注作为"过去标注"分类（初始 = 全量标注）。
2. **扫描过程中**：每判定一个过去标注为**仅死链（dead）/ 仅受限（blocked）**，它**立即**进入对应结果分类（标记状态 ⚑ 保留在结果行上），从"过去标注"实时移出。已判定问题的标注不在"过去标注"中重复出现。
3. **扫描完成（理想情况）**：所有过去标注要么被判死链/受限（进结果分类）、要么被判健康而清出 → "过去标注"分类**为空**。
4. **残留（唯一来源）**：仅"过去标记、但本次判定**不再是死链/受限**（活链 ok/skipped，或未被本次覆盖）"的记录会残留，出现在一次扫描完成的结果列表之中（追加于结果下方的未覆盖标注）。

## 3. 导入记录（设置备份恢复）

设置备份（`src/options.js` 导出/导入）携带整个 `chrome.storage.local`，含 `deadLastScan`（上次扫描结果）与 `deadMarks`（过去标注），导入时原样覆盖恢复。

用户提出两种可选方案，**当前实现采用方案 1（自然残留）**：

- **方案 1（精确，与 §2 残留语义一致）**：导入后不派生出独立的"过去标注"，直接按 §2.4 的残留规则自然计算——导入的死链/受限记录进入对应结果分类；`deadMarks` 中**未被结果覆盖**的记录（活链但过去被标记、或未被覆盖）即为"过去标注"残留。全覆盖导入 → 0；含活链但过去被标记的导入 → 非 0。
- **方案 2（简单，用户亦接受）**：导入时直接无视"活链但过去被标记"的可能性，**导入后"过去标注"强制 = 0**。实现需要区分"导入来源"（否则无法在不破坏数据结构的前提下归 0），当前**未实现**。

## 4. 计数

- "过去标注"分段计数 = 当前尚未流入结果分类的 `deadMarks` 数量（扫描中逐条判定而递减；导入场景按 §3 方案 1 自然残留计算）。

## 附：当前实现对照（4.0.7）

| 原则 | 当前实现（4.0.7） | 一致 |
|---|---|---|
| 开始新检测 = 全量过去标注 | `markedRows()`：无 `lastScan` 时 `showAll` 全量（marked-only 视图）；扫描中剔除已判问题标注 | ✅ |
| 扫描中实时流入死链/受限 | `liveRows()` 渲染已判定问题行；`markedRows()` 以 `covered = liveRows()` 剔除 | ✅ |
| 扫描完成理想为空 | 全覆盖（所有标注被判死链/受限）时 `markedRows()` 无残留 → "过去标注"空，"全部"视图不渲染空标注列表壳；"上次标注"视图回退可执行 start 空态 | ✅（全覆盖场景） |
| 残留 = "活链但过去标记" | `onCacheWritten` **不再 prune** 健康标注；健康（ok/skipped）或未探测的标注保留在 `deadMarks`，作为残留追加于结果下方、"上次标注"分段计数并可在该视图单独查看 | ✅ |
| 导入后"过去标注" = 0 | 备份导入原样恢复 `deadMarks` + `deadLastScan`；按 §2.4 自然残留计算（方案 1）——全覆盖导入为 0，含活链但过去标记的导入非 0；"简单方案"（强制归 0）未实现 | 采用方案 1 |
