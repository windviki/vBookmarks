# Dead 视图"过去标注"分类语义

本文档定义死链视图（`src/view-dead.js`）"过去标注"分类的语义原则，作为实现与后续改动的规范。

## 1. 定义

- **`deadMarks`**（store key `deadMarks`，id 数组）：用户在死链视图通过 ⚑ / `M` 键 / 选择模式批量标记的书签 id 集合。它独立于扫描结果持久化，是"过去标注"的数据来源。
- **"过去标注"分类**：相对于一次新检测的"待定"集合——开始新检测时它是过去所有标注；随着检测逐条给出判定，被判定为死链/受限的标注实时流入对应结果分类。

## 2. 生命周期（一次新检测）

1. **开始新检测**：把过去所有标注作为"过去标注"分类（初始 = 全量标注）。
2. **扫描过程中**：每判定一个过去标注为**仅死链（dead）/ 仅受限（blocked）**，它**立即**进入对应结果分类（标记状态 ⚑ 保留在结果行上），从"过去标注"实时移出。已判定问题的标注不在"过去标注"中重复出现。
3. **扫描完成（理想情况）**：所有过去标注要么被判死链/受限（进结果分类）、要么被判健康而清出 → "过去标注"分类**为空**。
4. **残留（唯一来源）**：仅"过去标记、但本次判定**不再是死链/受限**（活链 ok/skipped，或未被本次覆盖）"的记录会残留，出现在一次扫描完成的结果列表之中（追加于结果下方的未覆盖标注）。

## 3. 导入记录（设置备份恢复）

设置备份（`src/options.js` 导出/导入）携带整个 `chrome.storage.local`，含 `deadLastScan`（上次扫描结果）与 `deadMarks`（过去标注），导入时原样覆盖恢复。

导入场景遵循**简单方案**：

- **保持导入导出数据结构不变，不派生"过去标注"**。
- 导入的死链/受限记录进入对应结果分类（仅死链/仅受限）；导入的 `deadMarks` **不**单独形成"过去标注"分类 → **导入后"过去标注" = 0**。
- 即：导入时直接无视"活链但过去被标记"的可能性，不因它残留记录。

## 4. 计数

- "过去标注"分段计数 = 当前尚未流入结果分类的 `deadMarks` 数量（扫描中逐条判定而递减；导入场景为 0）。

## 附：当前实现对照（4.0.7）

| 原则 | 当前实现（4.0.7） | 一致 |
|---|---|---|
| 开始新检测 = 全量过去标注 | `markedRows()`：无 `lastScan` 时 `showAll` 全量；扫描中剔除已判问题标注 | ✅ |
| 扫描中实时流入死链/受限 | `liveRows()` 渲染已判定问题行；`markedRows()` 以 `covered = liveRows()` 剔除 | ✅ |
| 扫描完成理想为空 | `onCacheWritten`（`view-dead.js:1057-1064`）将健康标注（ok/skipped）从 `deadMarks` **prune 清除**；问题标注进入结果分类 | 结果一致，机制不同（清除 vs 残留） |
| 残留 = "活链但过去标记" | 现状为**健康即清除**，不残留显示；残留仅可能来自扫描后新增 / 未入结果的标记 | ❌ 差异 |
| 导入后"过去标注" = 0 | 备份导入原样恢复 `deadMarks` + `deadLastScan`；活链标记会出现在"过去标注"分类（非 0） | ❌ 差异 |
